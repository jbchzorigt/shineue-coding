## A1.4.1 Интерпретатор ба компиляторын хөрвүүлэх процесс <HL />

> 🎯 **Зорилго:** **Evaluate** the translation processes of interpreters and compilers — хөрвүүлэх аргуудын давуу ба сул талыг жинлэж, нөхцөлд тохирсон дүгнэлт гаргах. Энэ хэсгийн төгсгөлд та:
>
> - Интерпретатор ба компилятор программыг хэрхэн хөрвүүлдгийг тайлбарлана;
> - Байткодын интерпретатор ба JIT компиляц хоёр аргын санааг хэрхэн хослуулдгийг тайлбарлана;
> - Дөрвөн аргыг алдаа илрүүлэх, хөрвүүлэх хугацаа, зөөвөрлөх чадвар, хэрэглээгээр үнэлнэ;
> - Хурдан хөгжүүлэлт, гүйцэтгэл чухал, олон платформын нөхцөлд арга сонгож, үндэслэнэ.

### 🤔 Бодоод үзээрэй

Та Python дээр `print("Сайн уу")` гэж бичээд Run дарлаа — үг дэлгэцэнд шууд гарч ирлээ. CPU яагаад Python кодыг шууд гүйцэтгэж чадахгүй вэ? Run дарахаас үг гарах хооронд «ард нь» юу болсон бэ?

<details>
<summary>Хариу</summary>

CPU зөвхөн өөрийн **командын олонлогийн (instruction set)** хоёртын (binary) командыг ойлгодог — `print` гэдэг үг түүнд утгагүй. Run дарахад Python таны кодыг машины ойлгох хэлбэрт хөрвүүлж, тэр дор нь гүйцэтгэсэн. C, C++ зэрэг хэлэнд харин кодыг эхлээд бүхэлд нь хөрвүүлж, тусдаа `.exe` файл гаргадаг — энэ хоёр аргын ялгаа бол энэ хэсгийн гол сэдэв.

### 📖 Гол ойлголт

Хүнд ойлгомжтой **өндөр түвшний хэл (high-level language)** дээр бичсэн кодыг **эх код (source code)** гэнэ. Эх код hardware-аас хамаардаггүй, харин машины код тухайн CPU-д зориулагдсан хоёртын команд (жишээ нь `10110000 00000101`). Эх кодыг машины код руу хөрвүүлдэг программыг **хөрвүүлэгч (translator)** гэнэ. Хөрвүүлэгчийн хоёр үндсэн төрөл бол интерпретатор ба компилятор.

#### Интерпретатор (interpreter)

**Интерпретатор (interpreter)** эх кодыг мөр мөрөөр (командаар) хөрвүүлж, мөр бүрийг хөрвүүлмэгцээ гүйцэтгэнэ. Тусдаа машины кодын файл үүсгэдэггүй тул программ ажиллах бүрд хөрвүүлэлт дахин хийгдэнэ. Доорх зургийг дээрээс доош уншина: зүүн талын сум 1–3-р алхам мөр бүрд давтагддагийг харуулна.

```text
Эх код
  │
  ▼
┌──▶ 1. Дараагийн мөрийг авна
│    2. Тэр мөрийг хөрвүүлнэ
│    3. Шууд гүйцэтгэнэ → гаралт
└─── мөр үлдсэн бол 1 рүү буцна
```

- **Давуу тал:** шууд эхэлж, үр дүнг тэр дор нь харуулна — туршилт, алдаа засах, сурахад тохиромжтой. Интерпретатор суусан ямар ч платформ дээр ижил эх код ажиллана.
- **Сул тал:** нийтдээ удаан — 1000 удаа эргэх давталтын биеийг цэвэр интерпретатор зарчмын хувьд 1000 удаа дахин хөрвүүлнэ. Алдаа тэр мөр гүйцэтгэгдэх үед л илэрнэ.
- **Жишээ хэлнүүд:** Python, JavaScript, Ruby.

#### Компилятор (compiler)

**Компилятор (compiler)** программыг ажиллуулахаас **өмнө** эх кодыг бүхэлд нь хөрвүүлнэ. Энэ үйлдлийг **компиляц (compilation)** гэнэ. Үр дүн нь бие даан ажилладаг **гүйцэтгэх файл (executable)** — машины код. Түүнийг дахин хөрвүүлэлгүйгээр олон удаа ажиллуулна.

Компиляц таван шаттай, шат бүрийн үр дүн дараагийн шатны оролт болно: **лексик шинжилгээ (lexical analysis)** кодыг жижиг нэгж (token) болгон хуваана → **синтакс шинжилгээ (syntax analysis)** хэлний дүрмийг шалгана → **утгын шинжилгээ (semantic analysis)** хувьсагч зарлагдсан эсэх, төрөл таарахыг шалгана → **оновчлол (optimisation)** кодыг хурдан болгоно → **код үүсгэх (code generation)** машины кодыг гаргана. Шатуудыг нэрлэж таних түвшинд мэдэхэд хангалттай.

- **Давуу тал:** хурдан ажиллана, тухайн hardware-т оновчлогдсон; машины кодоос эх кодыг сэргээх (reverse-engineer) хэцүү.
- **Сул тал:** компиляц хугацаа шаарддаг; компиляцын (хөрвүүлэлтийн) алдаа бүрийг засахаас нааш программ ажиллахгүй; платформ (CPU + OS) бүрд тусад нь компиляц хийнэ — Windows дээр гаргасан `game.exe` macOS дээр ажиллахгүй.
- **Жишээ хэлнүүд:** C, C++. Java ч компиляц хийгддэг, гэхдээ машины код руу биш, байткод руу.

**Зүйрлэл.** Интерпретатор бол **хэлмэрч**: таныг уншиж байхад өгүүлбэр бүрийг тэр дор нь орчуулна. Шууд ойлгоно, гэхдээ дахин уншихад дахиад орчуулах хэрэгтэй. Компилятор бол **номын орчуулагч**: эхлээд номыг бүхэлд нь орчуулж хэвлэнэ. Хүлээх хэрэгтэй, гэхдээ дараа нь саадгүй уншина.

#### Байткод ба JIT компиляц

Бодит системүүд хоёр аргын санааг хослуулдаг. **Байткодын интерпретатор (bytecode interpreter)** эх кодыг эхлээд **байткод (bytecode)** руу хөрвүүлнэ. Байткод бол CPU-ийн биш, **виртуал машин (virtual machine, VM)** гэдэг программын ойлгодог нягт, платформоос хамааралгүй код. VM байткодыг команд командаар нь тайлбарлан гүйцэтгэнэ.

```text
program.py → [CPython доторх компилятор] → байткод
байткод → Python VM (Windows) → CPU
байткод → Python VM (Linux)   → CPU
байткод → Python VM (macOS)   → CPU
```

Эхний мөрөнд эх код байткод болно; дараагийн гурван мөр ижил байткодыг VM бүхий дурын платформ ажиллуулж чадахыг харуулна (Java-ийн JVM ч ийм). Бүрэн компиляц хийсэн машины кодоос удаан, учир нь VM байткодыг ажиллах үед нь тайлбарладаг. IB болон энэ хичээл Python-ийг «интерпретатортой хэл» гэж хялбарчилж ангилдаг, харин бодит CPython бол байткодын интерпретатор: файлыг бүхэлд нь байткод руу хөрвүүлээд, VM дээр гүйцэтгэдэг. Үндсэн скриптийн байткод санах ойд л байдаг, харин import хийсэн модулийнхыг `__pycache__` хавтсанд `.pyc` файл болгон кэшлэдэг.

**JIT компиляц (just-in-time compilation):** VM байткодыг гүйцэтгэж байхдаа байнга давтагддаг хэсгийг — **hot spot**-ыг — илрүүлж, ажиллах үед нь машины код руу хөрвүүлээд хадгална (cache); дараагийн удаа тэр хэсэг шууд машины кодоор хурдан ажиллана. PyPy (JIT-тэй Python), JVM, .NET, браузерын JavaScript JIT ашигладаг. Богино скриптэд JIT бараг ашиггүй — hot spot илрүүлж хөрвүүлэх нэмэлт зардал нөхөгдөх хугацаа олдохгүй, харин өдөржин ажилладаг сервер дээр маш үр ашигтай.

#### Алдаа хэзээ илэрдэг вэ?

| Алдааны төрөл | Жишээ | Компилятор | Интерпретатор |
|---|---|---|---|
| Синтакс алдаа (syntax error) — хэлний дүрэм зөрчсөн | `if True` (`:` дутуу) | Ажиллахаас өмнө | Тэр мөрт хүрэхэд |
| Утгын алдаа (semantic error) — дүрэм зөв ч утгагүй | Зарлаагүй хувьсагч ашиглах | Заримыг нь ажиллахаас өмнө | Тэр мөрт хүрэхэд |
| Логик алдаа (logic error) — ажиллана, хариу буруу | Гурван тооны нийлбэрийг 2-т хувааж дундаж олох | Илрүүлэхгүй — тест хэрэгтэй | Илрүүлэхгүй — тест хэрэгтэй |

Python (CPython) синтакс алдааг байткод руу хөрвүүлэх үедээ, юу ч ажиллахаас өмнө олдог. Зарлаагүй хувьсагч зэрэг бусад алдааг тэр мөрт хүрэхэд л олно. Алдааны төрлүүдийг B2.1 модульд дэлгэрэнгүй.

#### Дөрвөн шалгуураар үнэлэх

Хүснэгтийн мөр бүр нэг шалгуур, багана бүр нэг арга. Evaluate хариултад нэг мөрийн дагуу аргуудыг хооронд нь харьцуулна.

| Шалгуур | Компилятор | Интерпретатор | Байткодын интерпретатор | JIT компиляц |
|---|---|---|---|---|
| Алдаа илрүүлэх (error detection) | Синтакс (+ зарим утгын) алдааг ажиллахаас өмнө | Ажиллах үед, тэр мөрт хүрэхэд | Заримыг байткод руу хөрвүүлэхэд, бусдыг ажиллах үед | Байткодынхтой адил; нэмээд ажиллах явцад оновчилно |
| Хөрвүүлэх хугацаа (translation time) | Эхэндээ урт, дараа нь хурдан ажиллана | Шууд эхэлнэ, нийтдээ удаан | Дунд зэрэг эхлэл, дунд зэрэг хурд | Хурдан эхэлнэ, hot spot хөрвүүлэгдэх тусам хурдасна |
| Зөөвөрлөх чадвар (portability) | Бага — платформ бүрд дахин компиляц | Өндөр — интерпретатор хэрэгтэй | Өндөр — ямар ч VM дээр | Өндөр, платформд тохирсон оновчлолтой |
| Хэрэглээ (applicability) | Гүйцэтгэл чухал программ, системийн программ | Хурдан хөгжүүлэлт, скрипт, сургалт | Олон платформын апп | Урт хугацаанд ажилладаг сервер, вэб апп |

#### Гурван нөхцөл

| Нөхцөл | Сонголт | Яагаад | Жишээ |
|---|---|---|---|
| Хурдан хөгжүүлэлт, туршилт (rapid development and testing) | Интерпретатор | Өөрчлөлтийг шууд ажиллуулж, хурдан давтана | Стартап Python дээр вэб аппын прототип хийх |
| Гүйцэтгэл чухал (performance-critical) | Компилятор | Бүх программыг хурдан машины код болгож оновчилно | Хоцрогдол маш бага байх ёстой C++ арилжааны систем; сургуулийн робот тэмцээний Arduino (C++) |
| Олон платформ (cross-platform) | Байткод + JIT | Ижил байткод ямар ч VM дээр; JIT хурдыг нөхнө | Windows, macOS, Linux дээр ажиллах Java программ |

**Evaluate хариултын бүтэц (A1.3.4 хэсгийн C-S-L-J):** **C** — нөхцөл, **S** — давуу тал, **L** — сул тал, **J** — энэ нөхцөлд аль нь илүү вэ гэсэн дүгнэлт. Жишээ: *«For a real-time trading system a compiler is more appropriate, because fully optimised machine code gives the lowest latency, even though the code must be recompiled for each platform.»*

### 💻 Туршиж үзээрэй

`syntax_error_demo.py`-г заавал **файл** болгож хадгалаад ажиллуулна (Python shell-д мөр мөрөөр бичвэл өөр үр дүн гарна). Тиймээс хоёр файлыг «Өөрийн компьютер дээр ажиллуулж үзээрэй» (Python 3, IDLE эсвэл Thonny).

**1. `translation_lab.py` — ажиллах үеийн алдаа (runtime error) ба байткод:**

```python
import dis

def greet(name):
    print("Hello, " + name + "!")

greet("Alice")
try:
    # Intentional error: 'name' only exists inside greet()
    print("The length of the name is " + str(len(name)))
except NameError as e:
    print("Runtime error detected only when this line ran:", e)

def total(n):
    s = 0
    for i in range(n):
        s += i
    return s

dis.dis(total)    # print the bytecode that the Python VM runs
```

Гаралт (Python 3.12; `dis`-ийн гаралтаас давталтын хэсгийг л үлдээсэн):

```text
Hello, Alice!
Runtime error detected only when this line ran: name 'name' is not defined
...
        >>   28 FOR_ITER                 7 (to 46)
...
             38 BINARY_OP               13 (+=)
             42 STORE_FAST               1 (s)
             44 JUMP_BACKWARD            9 (to 28)
...
```

**2. `syntax_error_demo.py` — ажиллахаас өмнө илэрсэн алдаа:**

```python
print("Hello, World!")

# Intentional error: missing colon
if True
    print("This line has a syntax error")
```

- `Hello, Alice!` хэвлэгдсэний **дараа** алдаа гарсан: алдаатай мөрт хүрэх хүртэлх мөрүүд ажилласан. `try/except` алдааг барьсан тул программ үргэлжилсэн, байхгүй бол тэнд зогсоно.
- `syntax_error_demo.py` юу ч хэвлэхгүй, зөвхөн `SyntaxError: expected ':'` (4-р мөр) гарна: Python файлыг бүхэлд нь байткод руу хөрвүүлдэг, синтакс алдаа тэр алхмыг зогсоох тул эхний `print` ч ажиллахгүй. `if True:` болгож засвал хоёр мөр хоёулаа хэвлэгдэнэ.
- `dis`-ийн мөр бүрд байткод дахь байрлал (28), командын нэр, аргумент байна; `>>` бол үсрэлтийн очих цэг. `FOR_ITER` давталтыг эхлүүлж, `JUMP_BACKWARD` буцааж үсэрнэ. Эдгээр нь Python VM-ийн команд тул машины код биш (гаралт Python-ийн хувилбараас хамаарч өөр).

<Callout type="warning">
**⚠️ Анхаарах зүйлс**

- **«Компилятор бүх алдааг олно» гэдэг буруу.** Синтакс ба зарим утгын алдааг олно, логик алдааг аль ч арга урьдчилан олохгүй.
- **Байткод бол машины код биш.** CPU түүнийг шууд гүйцэтгэхгүй — VM хэрэгтэй.
- Хэл өөрөө биш, түүний **хэрэгжүүлэлт (implementation)** хөрвүүлэх аргыг тодорхойлдог: ижил Python кодыг CPython байткодоор, PyPy JIT-ээр ажиллуулна.
- Evaluate хариултад шалгуурыг нэрлээд, **дүгнэлтээ** заавал бич. Давуу, сул талыг жагсаагаад орхивол бүтэн оноо авахгүй.

</Callout>

| Машины код | Machine code (object code) | CPU шууд гүйцэтгэдэг хоёртын команд |
| Интерпретатор | Interpreter | Мөр бүрийг хөрвүүлж, тэр дор нь гүйцэтгэдэг хөрвүүлэгч |
| Компилятор | Compiler | Бүх кодыг ажиллахаас өмнө хөрвүүлж, гүйцэтгэх файл гаргадаг хөрвүүлэгч |
| Гүйцэтгэх файл | Executable | Бие даан ажилладаг машины кодын файл (`.exe`) |
| Байткод | Bytecode | VM гүйцэтгэдэг, платформоос хамааралгүй завсрын код |
| Виртуал машин | Virtual machine (VM) | Байткодыг тайлбарлан гүйцэтгэдэг программ |
| JIT компиляц | Just-in-time (JIT) compilation | Байнга гүйцэтгэгддэг хэсгийг (hot spot) ажиллах үед машины код болгож хадгалах |
| Зөөвөрлөх чадвар | Portability | Ижил программ өөр платформ дээр өөрчлөлтгүй ажиллах чадвар |
| Ажиллах үеийн алдаа | Runtime error | Программ ажиллаж байхад, тэр мөрт хүрэхэд илрэх алдаа |

### ✅ Өөрийгөө шалга

**1.** Python файлын 500-р мөрөнд зарлаагүй хувьсагч ашигласан алдаа байна. Программ 1-р мөрөөс эхэлж ажиллана. Алдаа хэзээ илрэх вэ? 500-р мөр нөхцөл нь хэзээ ч үнэн болдоггүй `if`-ийн дотор байвал яах вэ?

<details>
<summary>Хариу</summary>

Зөвхөн 500-р мөр гүйцэтгэгдэх үед; түүнээс өмнөх мөрүүд хэвийн ажиллана. Тэр мөрт хэзээ ч хүрэхгүй бол алдаа огт илрэхгүй — нуугдмал алдаа хожим хэрэглэгч дээр гэнэт гарч болзошгүй. Харин хаалт дутуу зэрэг **синтакс** алдаа байсан бол Python түүнийг байткод руу хөрвүүлэх үедээ, 1-р мөр ч ажиллахаас өмнө олно.

</details>

**2.** *Describe the process of just-in-time (JIT) compilation and explain how it combines elements of both interpretation and compilation.* [4]

<details>
<summary>Хариу</summary>

- Эх кодыг эхлээд байткод руу хөрвүүлж, VM түүнийг тайлбарлан гүйцэтгэнэ [1];
- VM байнга ажилладаг хэсгүүдийг (hot spots) хянаж илрүүлнэ [1];
- эдгээрийг ажиллах үед нь машины код руу хөрвүүлнэ [1];
- хөрвүүлсэн кодыг хадгалж (cache), дараагийн удаа ашигладаг — интерпретацийн зөөвөрлөх чадварыг компиляцын хурдтай хослуулна [1].

</details>

**3.** Нэг баг Android ба iOS-т зориулж хурдан, аюулгүй байх ёстой банкны гар утасны апп хийнэ. Аль хөрвүүлэх аргыг сонгохыг хоёр шалгуураар **Evaluate** хийгээрэй (4–5 өгүүлбэр). Нэг «зөв» сонголт байхгүй — шалгуураар үндэслэсэн тодорхой дүгнэлт л чухал.

<details>
<summary>Хариу</summary>

- **C:** Банкны апп хурдан, аюулгүй байх ёстой бөгөөд Android, iOS гэсэн хоёр л платформд ажиллана.
- **S:** Платформ бүрд компиляц хийсэн машины код тухайн hardware-т оновчлогдож хамгийн хурдан ажиллана (хөрвүүлэх хугацаа: эхэндээ урт, дараа нь хурдан); машины кодыг reverse-engineer хийхэд хэцүү нь аюулгүй байдалд тустай.
- **L:** Зөөвөрлөх чадвар бага: хоёр платформд тусад нь компиляц хийж, хоёр хувилбар гаргана, харин байткод + JIT нэг кодыг хоёуланд нь ажиллуулах байсан.
- **J:** Платформ ердөө хоёр тул хоёр удаа компиляц хийх нэмэлт ажил бага, харин хурд ба аюулгүй байдал энэ аппын гол шаардлага — тиймээс **платформ бүрд компиляц хийх** нь илүү тохиромжтой.

</details>

## Дүгнэлт

- **Интерпретатор** мөр бүрийг хөрвүүлж тэр дор нь гүйцэтгэнэ: шууд эхэлнэ, зөөвөрлөх чадвар өндөр, гэхдээ удаан, алдаа тэр мөрт хүрэхэд л илэрнэ.
- **Компилятор** бүх кодыг ажиллахаас өмнө хөрвүүлнэ: хурдан, оновчлогдсон, синтакс алдааг эхэнд нь олно, гэхдээ платформ бүрд дахин компиляц хийнэ.
- **Байткод + VM** нь платформоос хамааралгүй завсрын код; **JIT** hot spot-ыг ажиллах үед машины код болгож хурдасгана.
- Python (CPython) бол байткодын интерпретатор: синтакс алдаа юу ч ажиллахаас өмнө, зарлаагүй хувьсагч тэр мөрт хүрэхэд илэрнэ.

**Шалгалтад анхаар:**

- **Evaluate** (A1.4.1): C-S-L-J — нөхцөл, давуу тал, сул тал, энэ нөхцөлд тохирсон дүгнэлт. Дөрвөн шалгуурыг (алдаа илрүүлэх, хөрвүүлэх хугацаа, зөөвөрлөх чадвар, хэрэглээ) нэрээр нь ашигла.
- **Compare:** өгүүлбэр бүрт хоёр аргыг хоёуланг нь дурд («Compilers …, whereas interpreters …»), ижил талыг ч бич.
- **Describe** JIT: байткод → VM → hot spot → машины код → cache.
- Түгээмэл алдаа: «компилятор бүх алдааг олно», «`.exe` хаана ч ажиллана», «байткод бол машины код».
