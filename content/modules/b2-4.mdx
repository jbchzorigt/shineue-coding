## B2.4.1 Big O тэмдэглэгээ: алгоритм хэрхэн өсдөг вэ

> 🎯 **Зорилго:** **Describe** the efficiency of specific algorithms by calculating their Big O notation to analyse their scalability — алгоритмын Big O-г бодож, өгөгдөл өсөхөд алгоритм хурдаа хэр хадгалж чадахыг дэлгэрэнгүй тайлбарлах. Энэ хэсгийн төгсгөлд та:
>
> - Хугацааны ба санах ойн нарийн төвөгшил, Big O тэмдэглэгээг тодорхойлно;
> - Энгийн кодын Big O-г давталт тоолж, тогтмол үржвэр ба бага гишүүнийг хаяж олно;
> - n өсөхөд O(1), O(log n), O(n), O(n²), O(2ⁿ) хэрхэн өсөхийг харьцуулна;
> - Өгөгдлийн хэмжээ ба шаардлагад тохирох алгоритмыг сонгоно.

### 🤔 Бодоод үзээрэй

Ангийн багш 25 сурагчийн шалгалтын хуудсыг нэрээр нь цагаан толгойн дарааллаар 5 минутад өрсөн. Сургуулийн 1500 сурагчийн хуудсыг **яг ижил аргаар** өрвөл хэр удах вэ? Хуудас 60 дахин олон — гэхдээ ажил 60 дахин л нэмэгдэх үү? Кодгүйгээр хариулаарай:

1. `for i in range(5): print("hello")` — `print` хэдэн удаа ажиллах вэ? `range(5)`-ийг `range(n)` болговол?
2. `for i in range(n):` дотор `for j in range(n):`, түүн дотор `print("hi")`. n = 10 үед хэдэн удаа хэвлэх вэ?
3. `value = int(input())`, дараа нь `total = 50 + value`. `value` нь 1 000 000 бол хэдэн алхам хийх вэ?

<details>
<summary>Хариу</summary>

1. 5 удаа; `range(n)` бол n удаа — ажил n-тэй хамт өснө.
2. 10 × 10 = **100** удаа: гаднах давталтын дамжилт бүрт доторх нь бүтэн 10 удаа ажиллана (B2.3.3).
3. Утга хэд ч байсан **2** алхам. Оролтын **утга** биш, оролтын **хэмжээ** (хэдэн өгөгдөл) чухал.

Хэрэв гараар өрөх арга тань хуудас бүрийг бусад бүх хуудастай харьцуулдаг бол (2-р асуултын давхар давталт шиг) ажил 60 дахин биш, ойролцоогоор 60 × 60 = 3600 дахин өснө: 5 минут 12 гаруй хоног болно.

</details>

### 📖 Гол ойлголт

**Хугацааны нарийн төвөгшил (time complexity)** нь алгоритм хэдэн **алхам** хийхийг, **санах ойн нарийн төвөгшил (space complexity)** нь хэр их санах ой шаардахыг хэлнэ. **Big O тэмдэглэгээ (Big O notation)** нь оролтын хэмжээ n өсөхөд эдгээр хэрхэн өсөхийн **дээд хязгаарыг** илэрхийлнэ. Бид нэг компьютер дээрх секундийг биш, n томрох үеийн **өсөлтийн хурдыг** сонирхоно: секунд компьютер бүрт өөр, алхмын тоо өөрчлөгдөхгүй. Өгөгдөл өсөхөд алгоритм хурдаа хэр хадгалж чадахыг **өргөтгөх чадвар (scalability)** гэнэ.

IB ба сурах бичиг Big O-г **хамгийн муу тохиолдлоор (worst case)** өгдөг — энэ модуль ч ингэнэ. Бодит шинжилгээнд **хамгийн сайн тохиолдол (best case)** ба дундаж тохиолдлыг (average case) тусад нь бичдэг: жишээ нь хөөсөн эрэмбэлэлт хамгийн муу тохиолдолд O(n²), хамгийн сайн тохиолдолд (эрт зогсох тэмдэгтэй бол) O(n) (B2.4.3).

#### Big O-г давталт тоолж олох

```python
for i in range(n):            # n repetitions
    print("hello")            # -> O(n)

for i in range(n):            # n x n repetitions
    for j in range(n):
        print("hello")        # -> O(n^2)

for i in range(n):            # n x (n + 3) = n^2 + 3n repetitions
    for j in range(n + 3):
        print("hello")        # -> still O(n^2)

value = int(input())          # a fixed number of steps
total = 50 + value            # -> O(1)
```

| Дүрэм | Жишээ | Big O |
|---|---|---|
| n элемент дээрх нэг давталт | `for i in range(n)` | O(n) |
| Давталт дотор давталт: **үржүүл** | n × n | O(n²) |
| Тогтмол үржвэрийг хая | 25n² | O(n²) |
| Хамгийн хурдан өсөх гишүүнийг л үлдээ | n² + 3n | O(n²) |
| n-ээс хамаарах давталт байхгүй | хоёр мөр | O(1) |
| Дамжилт бүрт n-ийг хагасална | `while n > 1: n = n // 2` | O(log n) |

Хүснэгтийн мөр бүр нэг дүрэм: дүрэм, жишээ, үр дүнгийн Big O. **log n** (log₂ n) нь n-ийг 1 болтол хэдэн удаа хоёрт хуваахыг хэлнэ: 1024 → 512 → … → 1 бол 10 удаа, учир нь 2¹⁰ = 1024.

Яагаад хаядаг вэ? n = 1000 үед n² = 1 000 000, харин 3n = 3000 буюу нийтийн 0.3% орчим (💻 дээр шалгана). n томрох тусам бага гишүүн ба тогтмол үржвэрийн жин алга болно. Энэ бол хялбарчлал: жижиг n-д тогтмол үржвэр мэдэгдэхүйц нөлөөлдөг тул Big O бодит секундийг таамаглахгүй.

#### Өсөлтийн хурдыг харьцуулах

| Big O | Нэр | Жишээ | n = 1024 үед алхам |
|---|---|---|---|
| O(1) | Тогтмол (constant) | `numbers[i]`-д хандах; стекийн push, pop (B2.2.3) | 1 |
| O(log n) | Логарифм (logarithmic) | Хоёртын хайлт (B2.4.2) | 10 |
| O(n) | Шугаман (linear) | Шугаман хайлт (B2.4.2) | 1024 |
| O(n log n) | n log n | Quicksort-ын дундаж тохиолдол (B2.4.4, HL) | 10 240 |
| O(n²) | Квадрат (quadratic) | Хөөсөн, сонгон эрэмбэлэлт (B2.4.3) | ≈ 1 сая |
| O(2ⁿ) | Экспоненциал (exponential) | Энгийн рекурсив Fibonacci (B2.4.4, HL) | 300 гаруй оронтой тоо |

Мөр бүр нэг өсөлтийн ангилал; сүүлийн багана n = 1024 үед ойролцоогоор хэдэн алхам болохыг харуулна. Том n-д: `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`. O(2ⁿ)-д n **нэгээр** өсөх бүрт ажил **хоёр дахин** нэмэгдэнэ.

#### Санах ойн нарийн төвөгшил

```python
total = 0                     # O(1) space: total and i are overwritten
for i in range(n):
    total = total + i

squares = []                  # O(n) space: the list grows with n
for i in range(n):
    squares.append(i * i)
```

- **Хувьсагч ба тогтмол:** n-ээс үл хамаарах тогтмол хэмжээ → O(1).
- **Оролт ба өгөгдлийн бүтэц:** n элементтэй жагсаалт → O(n); n × n хүснэгт (B2.2.2) → O(n²).
- **Гүйцэтгэл:** рекурсив дуудлага бүр параметр, буцах хаягаа стекэд хадгалдаг тул дуудлага бүрт нэмэлт санах ой (B2.4.4, HL).
- **Хурд ба санах ойн тэнцвэр (trade-off):** ихэнхдээ хурдыг санах ойгоор «худалдаж авдаг» — илүү санах ой ашиглаад хугацаа хэмнэнэ.

### 💻 Туршиж үзээрэй

Алхмуудыг **секундээр биш, тоогоор** хэмжинэ — компьютер бүрт адилхан гарна. O(2ⁿ)-ийг тоолохгүй, `2 ** n`-ээр шууд бодно: n = 64 үед 2⁶⁴ алхмыг секундэд тэрбумаар тоолсон ч 500 гаруй жил болно. Ажиллуулахаасаа өмнө n = 8 мөрийг таамагла:

```python
def constant(n):          # O(1)
    return 1

def logarithmic(n):       # O(log n): halve n until it reaches 1
    steps = 0
    while n > 1:
        n = n // 2
        steps += 1
    return steps

def linear(n):            # O(n)
    steps = 0
    for i in range(n):
        steps += 1
    return steps

def quadratic(n):         # O(n^2)
    steps = 0
    for i in range(n):
        for j in range(n):
            steps += 1
    return steps

# :>6 means "right-align in 6 characters", so the columns line up
print(f"{'n':>6} {'O(1)':>6} {'O(log n)':>9} {'O(n)':>7} {'O(n^2)':>10} {'O(2^n)':>22}")
for n in [1, 8, 16, 32, 64, 1024]:
    if n <= 64:
        exponential = 2 ** n          # computed directly, not counted
    else:
        exponential = "too big"
    print(f"{n:>6} {constant(n):>6} {logarithmic(n):>9} {linear(n):>7} {quadratic(n):>10} {exponential:>22}")

n = 1000
exact = n * n + 3 * n
# :.1% shows a fraction as a percentage with one decimal place
print(f"\nn = {n}: n^2 + 3n = {exact}, n^2 alone = {n * n} ({n * n / exact:.1%} of the total)")
```

```text
     n   O(1)  O(log n)    O(n)     O(n^2)                 O(2^n)
     1      1         0       1          1                      2
     8      1         3       8         64                    256
    16      1         4      16        256                  65536
    32      1         5      32       1024             4294967296
    64      1         6      64       4096   18446744073709551616
  1024      1        10    1024    1048576                too big

n = 1000: n^2 + 3n = 1003000, n^2 alone = 1000000 (99.7% of the total)
```

1. n 16-аас 32 болж хоёр дахин өсөхөд багана бүр юу болох вэ? Багана бүрт дүрэм бич.
2. Гурвалсан давталттай `cubic(n)` нэмбэл n = 8 үед хэд гарах вэ? Big O нь юу вэ?
3. Сүүлийн хэсэгт `n = 10`, дараа нь `n = 1000000` гэж өөрчил. n² нийтийн хэдэн хувь болох вэ?

<details>
<summary>Хариу</summary>

1. O(1) өөрчлөгдөхгүй; O(log n) **1-ээр** нэмэгдэнэ (4 → 5); O(n) **2 дахин** (16 → 32); O(n²) **4 дахин** (256 → 1024); O(2ⁿ) өөрийнхөө **квадрат** болно (65 536² = 4 294 967 296).
2. 8 × 8 × 8 = **512** — O(n³).
3. n = 10 үед `76.9%`, n = 1 000 000 үед `100.0%` (бүр нарийвчилбал 99.9997%). n томрох тусам 3n-ийн жин алга болдог тул Big O түүнийг хаядаг.

</details>

<Callout type="warning">
**⚠️ Анхаарах зүйлс**

- **Big O бол секунд биш.** «O(n) алгоритм n секунд ажиллана» гэж бүү бич. Big O нь n өсөхөд ажил **хэрхэн өсөхийг** хэлнэ.
- **Дараалсан давталтууд нэмэгдэнэ, давхар давталт үржигдэнэ.** Хоёр тусдаа `for i in range(n)` бол n + n = 2n → O(n), O(n²) биш.
- **Доторх давталт n-ээс хамаарахгүй бол үржүүлэхэд n² гарахгүй.** `for i in range(n):` дотор `for j in range(3):` → 3n → O(n).
- **Жижиг өгөгдөлд Big O бүхнийг шийддэггүй.** Тогтмол үржвэр хаягдсан тул жижиг n-д O(n) алгоритм O(log n)-ээс хурдан байж болно. O(log n) нь n том болоход л баталгаатай давуу.

</Callout>

**1.** Big O-г бич: a) 1-ээс n хүртэлх давталт дотор 1-ээс 10 хүртэлх давталт; b) `while n > 1: n = n // 2`; c) 1 сая элементэд O(n²) ба O(n log n)-ийн алийг сонгох вэ, яагаад?

<details>
<summary>Хариу</summary>

- a) **O(n)** — 10n алхам, тогтмол 10-ыг хаяна.
- b) **O(log n)** — дамжилт бүрт n хагасална.
- c) **O(n log n)** — n = 1 000 000 үед n² = 10¹², харин n log n ≈ 2 × 10⁷: ойролцоогоор 50 000 дахин бага ажил.

</details>

**2.** Нөхцөл бүрт ямар Big O-той алгоритм эсвэл арга тохирохыг бич: a) 25 нэртэй ангийн жагсаалтыг улиралд нэг удаа эрэмбэлэх; b) эрэмбэлэгдсэн 50 сая харилцагчийн бүртгэлээс өдөрт олон удаа хайх; c) товч дарах бүрт шууд хариу өгөх ёстой тоглоом; d) ижил, жижиг дэд асуудлуудад хуваагддаг маршрут төлөвлөлт.

### 📖 Гол ойлголт

#### Шугаман хайлт

**Шугаман хайлт (linear search)** нь элемент бүрийг эхнээс нь дараалан **хайх утгатай (key)** харьцуулна (B2.2.2-т товч үзсэн). Жагсаалт эрэмбэлэгдсэн байх шаардлагагүй.

```python
def linear_search(numbers, key):
    for i in range(len(numbers)):
        if numbers[i] == key:
            return i          # found: stop at once
    return -1                 # every item checked: not found

print(linear_search([3, 9, 7, 4], 7))    # 2 (after 3 comparisons)
print(linear_search([3, 9, 7, 4], 5))    # -1 (after 4 comparisons)
```

- Хамгийн сайн тохиолдол: хайх утга эхэнд — 1 харьцуулалт. Хамгийн муу: сүүлд эсвэл огт байхгүй — n харьцуулалт.
- Хугацаа O(n), санах ой O(1) (зөвхөн `i`).
- Сурах бичгийн хувилбар олсон ч бүх элементийг шалгадаг. `return` функцийг тэр даруй дуусгадаг тул (B2.3.4) энд олмогц зогсоно.

#### Хоёртын хайлт

**Хоёртын хайлт (binary search)** нь зөвхөн **эрэмбэлэгдсэн (sorted)** жагсаалт дээр ажиллана. Хайх мужийн дунд элементийг харьцуулаад, хайх утга байж **боломжгүй** хагасыг хаяна. `lower` ба `upper` нь хайж буй мужийн эхний ба сүүлийн индекс, `mid` нь **дунд индекс**.

```python
def binary_search(numbers, key):
    lower, upper = 0, len(numbers) - 1    # upper is the LAST index
    while lower <= upper:
        mid = (lower + upper) // 2
        if numbers[mid] == key:
            return mid
        elif numbers[mid] < key:
            lower = mid + 1               # throw away the left half
        else:
            upper = mid - 1               # throw away the right half
    return -1                             # the range is empty: not found
```

`binary_search([3, 4, 5, 7, 9, 11, 13], 11)`-ийн мөшгилт:

| `lower` | `upper` | `mid` | `numbers[mid]` | Үйлдэл |
|---|---|---|---|---|
| 0 | 6 | 3 | 7 | `7 < 11` → `lower = 4` |
| 4 | 6 | 5 | 11 | тэнцүү → `5` буцаана |

Мөр бүр давталтын нэг дамжилт: дамжилтын эхэн дэх `lower`, `upper`, бодсон `mid`, тэнд байгаа утга, хийсэн үйлдэл. Давталт `lower > upper` болоход (муж хоосорход) зогсоно. Энэ модульд **давталтын нэг дамжилтыг нэг харьцуулалт** гэж тоолно — `==` ба `<`-ийг хоёуланг шалгасан ч. Энд 2 харьцуулалтаар оллоо; шугаман хайлт 6 хийх байсан.

Дамжилт бүр мужийг хагасалдаг тул хамгийн ихдээ ойролцоогоор log₂ n + 1 харьцуулалт хийнэ: 1024 элементэд 11, 1 000 000 элементэд **20** — шугаман хайлтад 1 000 000 хүртэл. Тогтмол +1-ийг хаявал хугацаа O(log n), санах ой O(1).

#### Сурах бичгийн алдаа: `upper` бол СҮҮЛИЙН индекс

Сурах бичгийн Python код `upper = len(numbers)` гэж эхэлдэг. 7 элементэд энэ нь 7 — сүүлийн индексээс (6) нэгээр хэтэрсэн тул бүх элементээс их утга (жишээ нь 20) хайхад `mid` 7 хүрч `IndexError` гарна. Зөв нь `upper = len(numbers) - 1`. Хайлтыг захын тохиолдлоор — эхний, сүүлийн, байхгүй утга, хоосон жагсаалт — заавал мөшги.

#### Аль хайлтыг сонгох вэ

| Нөхцөл | Сонголт | Яагаад |
|---|---|---|
| Нэрээр эрэмбэлсэн утасны жагсаалтаас **нэрээр** дугаар хайх | Хоёртын | Хайж буй талбараараа эрэмбэлэгдсэн → O(log n) |
| Тэр жагсаалтаас **дугаараар** эзний нэрийг хайх | Шугаман (эсвэл дугаараар эрэмбэлсэн хоёр дахь жагсаалт үүсгэх) | Дугаараар эрэмбэлэгдээгүй тул хагаслах боломжгүй |
| 50 хүрэхгүй ажилтнаас нэг ID-г нэг удаа хайх | Шугаман | Эхлээд эрэмбэлэх нь хэмнэлтээсээ үнэтэй |
| ID-аар эрэмбэлсэн 1500 сурагчаас хаягийг өдөрт олон удаа хайх | Хоёртын | Том, эрэмбэлэгдсэн, олон удаа хайдаг |

### 💻 Туршиж үзээрэй

Хоёр хайлт байрлал ба харьцуулалтын тоог хамт буцаана (`return i, comparisons` гэвэл хоёр утгыг хаалтанд хамт буцаадаг). Ажиллуулахаасаа өмнө таамагла:

```python
def linear_search(numbers, key):
    comparisons = 0
    for i in range(len(numbers)):
        comparisons += 1
        if numbers[i] == key:
            return i, comparisons
    return -1, comparisons

def binary_search(numbers, key):
    lower, upper = 0, len(numbers) - 1
    comparisons = 0
    while lower <= upper:
        mid = (lower + upper) // 2
        comparisons += 1                  # one pass = one comparison
        if numbers[mid] == key:
            return mid, comparisons
        elif numbers[mid] < key:
            lower = mid + 1
        else:
            upper = mid - 1
    return -1, comparisons

data = [3, 4, 5, 7, 9, 11, 13]
print("binary 11:", binary_search(data, 11))
print("binary 8 :", binary_search(data, 8))
big = list(range(1, 1_000_001))           # 1, 2, ..., 1 000 000
print("linear 999 999:", linear_search(big, 999_999))
print("binary 999 999:", binary_search(big, 999_999))
```

```text
binary 11: (5, 2)
binary 8 : (-1, 3)
linear 999 999: (999998, 999999)
binary 999 999: (999998, 19)
```

1. Хоёртын хайлт 19, шугаман хайлт 999 999 харьцуулалт хийсэн. Яагаад ийм их ялгаатай вэ?
2. **Алдаа ол:** `binary_search` доторх `len(numbers) - 1`-ийг `len(numbers)` болгоод `print(binary_search(data, 20))` гэж нэмж ажиллуул. Юу болох вэ, яагаад?

<details>
<summary>Хариу</summary>

1. Хоёртын хайлт дамжилт бүрт мужийг **хагасалдаг**: 1 000 000 → 500 000 → … → 1 болтол 20 орчим харьцуулалт (O(log n)). Шугаман хайлт 999 999-д хүртэл элемент бүрийг нэг нэгээр шалгана (O(n)).
2. `IndexError: list index out of range`. 20 бүхнээс их тул `lower` өссөөр 7 болж, `mid = (7 + 7) // 2 = 7` гарна, гэтэл сүүлийн индекс 6. Сурах бичгийн алдаа яг энэ.

</details>

### 📖 Гол ойлголт

**Эрэмбэлэх (sorting)** гэдэг нь өгөгдлийг **өсөх (ascending)** эсвэл **буурах (descending)** дарааллаар байрлуулах. Эрэмбэлэлтэд **дамжилт (pass)** гэж гаднах давталтын нэг удаагийн гүйлтийг — жагсаалтыг нэг удаа гүйж шалгахыг хэлнэ.

#### Хөөсөн эрэмбэлэлт

**Хөөсөн эрэмбэлэлт (bubble sort)** нь **хөрш (adjacent)** хоёр элементийг харьцуулж, буруу ээлжтэй бол **солино (swap)**. Нэг дамжилтын дараа хамгийн том утга төгсгөлд «хөөсөрч» гарна, тиймээс дараагийн дамжилт нэг элементээр эрт зогсоно (`- i`). Нэг ч солилт хийгээгүй дамжилт гарвал жагсаалт эрэмбэлэгдсэн байна — `swapped` **тэмдгээр (flag)** эрт зогсоно.

```python
numbers = [7, 3, 9, 2]
n = len(numbers)
for i in range(n - 1):
    swapped = False                       # reset at the start of EVERY pass
    for j in range(n - 1 - i):            # the last i items are already in place
        if numbers[j] > numbers[j + 1]:   # an adjacent pair in the wrong order
            temp = numbers[j]             # swap with temp (B2.1.1)
            numbers[j] = numbers[j + 1]
            numbers[j + 1] = temp
            swapped = True
    if not swapped:                       # a pass without swaps: already sorted
        break
print(numbers)                            # [2, 3, 7, 9]
```

Сурах бичгийн өгөгдлийг (16, 13, 4, 6, 22, 1, 9, 5) мөшгивөл:

| Дамжилт | Дамжилтын дараах жагсаалт | Харьцуулалт | Солилт |
|---|---|---|---|
| эхлэл | 16, 13, 4, 6, 22, 1, 9, 5 | | |
| 1 | 13, 4, 6, 16, 1, 9, 5, **22** | 7 | 6 |
| 2 | 4, 6, 13, 1, 9, 5, **16, 22** | 6 | 5 |
| 3 | 4, 6, 1, 9, 5, **13, 16, 22** | 5 | 3 |
| 4 | 4, 1, 6, 5, **9, 13, 16, 22** | 4 | 2 |
| 5 | 1, 4, 5, **6, 9, 13, 16, 22** | 3 | 2 |
| 6 | 1, 4, 5, 6, 9, 13, 16, 22 | 2 | 0 → зогсоно |

Мөр бүр нэг дамжилт; **тод** хэсэг эцсийн байрандаа очсон утгууд — дамжилт бүрт нэгээр уртасна. 6-р дамжилт солилтгүй тул 7-ын оронд 6 дамжилтаар зогслоо. Нийт **27** харьцуулалт, **18** солилт.

#### Сонгон эрэмбэлэлт

**Сонгон эрэмбэлэлт (selection sort)** жагсаалтыг зүүн талын **эрэмбэлэгдсэн** ба баруун талын **эрэмбэлэгдээгүй** хэсэгт хуваана. Дамжилт бүр эрэмбэлэгдээгүй хэсгийн **хамгийн бага** утгыг сонгож, тэр хэсгийн эхний байранд солино — дамжилтад нэг л солилт.

```python
numbers = [9, 7, 2, 3]
for i in range(len(numbers) - 1):
    min_index = i                          # the smallest so far: the first unsorted item
    for j in range(i + 1, len(numbers)):
        if numbers[j] < numbers[min_index]:
            min_index = j
    temp = numbers[i]                      # one swap per pass
    numbers[i] = numbers[min_index]
    numbers[min_index] = temp
print(numbers)                             # [2, 3, 7, 9]
```

| Дамжилт | Сонгосон хамгийн бага | Эрэмбэлэгдсэн хэсэг | Эрэмбэлэгдээгүй хэсэг |
|---|---|---|---|
| 1 | 1 | 1 | 13, 4, 6, 22, 16, 9, 5 |
| 2 | 4 | 1, 4 | 13, 6, 22, 16, 9, 5 |
| 3 | 5 | 1, 4, 5 | 6, 22, 16, 9, 13 |

### 💻 Туршиж үзээрэй

Хоёр эрэмбэлэлт жагсаалтын **хуулбар** дээр ажиллаж, харьцуулалт ба солилтыг тоолно. Python-ий `a, b = b, a` солилтыг ашигласан. Ажиллуулахаасаа өмнө «sorted» мөрийг таамагла:

```python
def bubble_sort(numbers):
    a = numbers[:]                         # a copy: the original stays unchanged
    comparisons = 0
    swaps = 0
    for i in range(len(a) - 1):
        swapped = False
        for j in range(len(a) - 1 - i):
            comparisons += 1
            if a[j] > a[j + 1]:
                a[j], a[j + 1] = a[j + 1], a[j]
                swaps += 1
                swapped = True
        if not swapped:
            break
    return comparisons, swaps

def selection_sort(numbers):
    a = numbers[:]
    comparisons = 0
    swaps = 0
    for i in range(len(a) - 1):
        min_index = i
        for j in range(i + 1, len(a)):
            comparisons += 1
            if a[j] < a[min_index]:
                min_index = j
        if min_index != i:                 # count only real moves
            a[i], a[min_index] = a[min_index], a[i]
            swaps += 1
    return comparisons, swaps

for name, data in [("textbook", [16, 13, 4, 6, 22, 1, 9, 5]),
                   ("sorted", [1, 2, 3, 4, 5, 6, 7, 8]),
                   ("reversed", [8, 7, 6, 5, 4, 3, 2, 1])]:
    print(name, "bubble", bubble_sort(data), "selection", selection_sort(data))
```

## B2.4.4 Рекурс: өөрийгөө дууддаг функц <HL />

> 🎯 **Зорилго:** **Explain** the fundamental concept of recursion and its applications in programming — рекурсын үндсэн ойлголт ба программчлалд хэрхэн хэрэглэгддэгийг шалтгаантай нь тайлбарлах. Энэ хэсгийн төгсгөлд та:
>
> - Рекурсыг суурь тохиолдол, ерөнхий тохиолдол, ороох, тайлах гэсэн нэр томьёогоор тайлбарлана;
> - Дуудлагын стек рекурсив дуудлага бүрийг хэрхэн хадгалж, яагаад санах ой зарцуулдгийг тайлбарлана;
> - Quicksort рекурсыг хувааж ялах аргад хэрхэн ашигладгийг тайлбарлана;
> - Рекурсын давуу ба сул тал, тохирох нөхцөлийг үнэлнэ.

### 🤔 Бодоод үзээрэй

Кино театрын харанхуй танхимд суугаад хэддүгээр эгнээнд байгаагаа мэдэхийг хүслээ. Урд суусан хүнээсээ асуухад тэр ч мөн урдахаасаа асууна — ингэсээр эхний эгнээний хүн «1» гэж шууд хариулна. Хариу буцахад хүн бүр 1-ийг нэмээд арын хүндээ дамжуулна. Хариулаарай:

1. 5! = 5 × 4 × 3 × 2 × 1. 5!-ийг 4!-ээр илэрхийл.
2. n!-ийг (n − 1)!-ээр илэрхийл. Хэзээ зогсох вэ?
3. B2.2 модульд үзсэн аль өгөгдлийн бүтэц «хаанаас ирснээ» санадаг вэ?

<details>
<summary>Хариу</summary>

1. 5! = 5 × 4!
2. n! = n × (n − 1)!; n = 1 үед зогсоно, учир нь 1! = 1. Кино театрын эхний эгнээний хүн шиг шууд хариулна.
3. **Стек** (B2.2.3): функцийн дуудлагуудыг дуудлагын стек санадаг.

</details>

### 📖 Гол ойлголт

**Рекурс (recursion)** гэдэг нь функц тодорхой нөхцөл биелэх хүртэл **өөрийгөө дуудах** явдал. Нөхцөл биелсний дараа хариу сүүлийн дуудлагаас эхний дуудлага руу буцаж бүтнэ — кино театрын асуулт урагшаа, хариу хойшоо явсан шиг.

| Хэсэг | Юу вэ | `factorial` дээр |
|---|---|---|
| **Суурь тохиолдол (base case)** | Өөрийгөө дууддаггүй, шууд хариу өгдөг төгсгөл. Байхгүй бол рекурс төгсгөлгүй — Python-д `RecursionError` гарч зогсоно | `n == 1` → 1 |
| **Ерөнхий тохиолдол (general case)** | Өөрийгөө **жижиг** оролтоор дуудаж, суурь тохиолдол руу ойртдог хэсэг | `n * factorial(n - 1)` |
| **Ороох (winding)** | Дуудлагууд гүнзгийрэх үе: дуудлага бүр доорхоо хүлээнэ | factorial(4) → (3) → (2) → (1) |
| **Тайлах (unwinding)** | Суурь тохиолдолд хүрсний дараа утгууд буцаж нийлэх үе | 1 → 2 → 6 → 24 |

```python
def factorial(n):
    if n == 1:                     # base case
        return 1
    return n * factorial(n - 1)    # general case
```

`factorial(4)`-ийг дуудахад:

```text
factorial(4)                       returns 4 × 6 = 24
 └─ factorial(3)                   returns 3 × 2 = 6
     └─ factorial(2)               returns 2 × 1 = 2
         └─ factorial(1)           base case: returns 1
↓ winding: calls go deeper         ↑ unwinding: values come back
```

`└─` нь дээрх дуудлага түүнийг дуудсаныг заана. Зүүн баганыг дээрээс доош уншвал ороох, баруун баганыг доороос дээш уншвал тайлах. Дуудлага бүр доорх дуудлагынхаа хариуг хүлээнэ; зөвхөн `factorial(1)` шууд хариулна.

#### Дуудлагын стек

B2.2.3-т **дуудлагын стек (call stack)** функцийн буцах хаяг, параметрийг хадгалдгийг үзсэн. Дуудлага бүр стекэд нэг **фрейм (stack frame)** push хийнэ: параметр, локал хувьсагч, буцах хаяг. Тайлах үед фреймүүд LIFO-оор pop хийгдэнэ: хамгийн сүүлд дуудсан `factorial(1)` хамгийн түрүүнд дуусна. n гүнтэй рекурс n фрейм зэрэг хадгалдаг тул санах ой O(n) (B2.4.1).

Суурь тохиолдол байхгүй бол фреймүүд овоорсоор стек дүүрнэ — **stack overflow**. Python-д үүнээс сэргийлж ойролцоогоор 1000 фреймд `RecursionError` гаргадаг (`sys.getrecursionlimit()` → 1000); зарим хэлэнд программ шууд унана.

#### Давуу ба сул тал

| Давуу тал | Сул тал |
|---|---|
| Нарийн асуудлыг цөөн мөр, цөөн хувьсагчаар гоё (elegant) шийднэ | Стекийг их ашигладаг тул санах ой их зарцуулж, stack overflow үүсгэж болно |
| Асуудлыг жижиг, ижил дэд асуудалд хуваах тул уншиж, шийдэхэд амар | Зогсох нөхцөл буруу бол төгсгөлгүй рекурс → программ унана (Python-д `RecursionError`) |
| Өөртэйгөө төстэй бүтэц ба асуудалд тохирно: фрактал зураг, хоёртын мод (binary tree, B4 модульд, HL), хувааж ялах эрэмбэлэлт (quicksort) | Давталтаас ихэвчлэн удаан: энгийн рекурсив Fibonacci өөрийгөө **хоёр** удаа дууддаг тул `fib(25)` 242 785 дуудлага хийнэ. Мөшгих, засварлахад хэцүү |

#### Quicksort: рекурсаар хувааж ялах

**Хувааж ялах (divide and conquer)** арга асуудлыг жижиг, ижил хэсгүүдэд хувааж, тус бүрийг шийднэ. Quicksort:

1. **Тулгуур элемент (pivot)** сонгоно — энд дунд элемент.
2. **Хуваалт (partition):** тулгуур элементээс бага утгуудыг зүүн, ихийг баруун тийш шилжүүлнэ.
3. Хэсэг бүрийг **рекурсаар** quicksort хийнэ.
4. Суурь тохиолдол: 0 эсвэл 1 элементтэй хэсэг аль хэдийн эрэмбэлэгдсэн.

```python
def quick_sort(numbers, start, finish, depth):
    if start >= finish:                          # base case: 0 or 1 item
        return
    left, right = start, finish
    pivot = numbers[(start + finish) // 2]       # the middle element
    while left <= right:
        while numbers[left] < pivot:             # this item can stay on the left
            left += 1
        while numbers[right] > pivot:            # this item can stay on the right
            right -= 1
        if left <= right:                        # both are on the wrong side: swap
            numbers[left], numbers[right] = numbers[right], numbers[left]
            left += 1
            right -= 1
    print("   " * depth + f"pivot {pivot}: {numbers[start:finish + 1]}")
    quick_sort(numbers, start, right, depth + 1)     # the left part
    quick_sort(numbers, left, finish, depth + 1)     # the right part

data = [16, 13, 4, 6, 22, 1, 9, 5]
quick_sort(data, 0, len(data) - 1, 0)
print("sorted:", data)
```

```text
pivot 6: [5, 1, 4, 6, 22, 13, 9, 16]
   pivot 1: [1, 5, 4]
      pivot 5: [4, 5]
   pivot 13: [9, 13, 22, 16]
      pivot 22: [16, 22]
sorted: [1, 4, 5, 6, 9, 13, 16, 22]
```

Мөр бүр нэг хуваалтын дараах хэсэг (`pivot` — тулгуур элемент); догол мөр бүр рекурсын нэг түвшин гүнзгийрснийг заана. 6-г тулгуур элемент болгосон хуваалтын дараа `[5, 1, 4]` ба `[22, 13, 9, 16]` тус тусдаа дахин хуваагдана. Quicksort дундаж тохиолдолд O(n log n) тул том өгөгдөлд O(n²) эрэмбэлэлтээс хамаагүй хурдан, гэхдээ тулгуур элемент байнга хамгийн бага эсвэл хамгийн их утга таарвал хамгийн муу тохиолдолд O(n²) болно.

**Рекурс тохирох эсэхийг дөрвөн асуултаар шалга:** суурь тохиолдлыг тодорхойлж чадах уу? Асуудлыг өөрийнх нь жижиг хувилбараар шийдэж болох уу? Өөртэйгөө төстэй бүтэц (мод, граф, холбоост жагсаалт) юм уу, буцаж хайх (backtracking) шаардлагатай юу? Санах ой, хугацааг хэт зарцуулалгүйгээр илүү ойлгомжтой болох уу?

### 💻 Туршиж үзээрэй

`depth` параметр дуудлага хэр гүнд байгааг тоолж, догол болгоно (түвшин бүрт 3 зай). Ажиллуулахаасаа өмнө мөр бүрийг таамагла:

```python
import sys

def factorial(n, depth):
    indent = "   " * depth
    print(f"{indent}factorial({n}) called")            # winding
    if n == 1:                                          # base case
        print(f"{indent}base case -> return 1")
        return 1
    result = n * factorial(n - 1, depth + 1)            # general case
    print(f"{indent}return {n} * ... = {result}")       # unwinding
    return result

def no_base_case(n):
    return no_base_case(n - 1)                          # nothing stops the calls

print("4! =", factorial(4, 0))
print("recursion limit:", sys.getrecursionlimit())
try:
    no_base_case(5)
except RecursionError as error:
    print("RecursionError:", error)
```

```text
factorial(4) called
   factorial(3) called
      factorial(2) called
         factorial(1) called
         base case -> return 1
      return 2 * ... = 2
   return 3 * ... = 6
return 4 * ... = 24
4! = 24
recursion limit: 1000
RecursionError: maximum recursion depth exceeded
```

1. Гаралтаас суурь тохиолдол, ороох, тайлахыг заа. `4! = 24` яагаад хамгийн сүүлд хэвлэгдсэн бэ?
2. `factorial(0, 0)` дуудвал юу болох вэ? 0! = 1 болохоор аль мөрийг засах вэ?

<details>
<summary>Хариу</summary>

1. `called` мөрүүд — ороох (догол нэмэгдэнэ), `base case` — суурь тохиолдол, `return` мөрүүд — тайлах (догол багасна). `print` эхлээд аргументаа — `factorial(4, 0)`-ийг — бүтэн бодож дуусгах ёстой тул бусад бүх мөр түрүүлж хэвлэгдэнэ.
2. n нь 0, −1, −2… болж хэзээ ч 1 болохгүй → `RecursionError`. `if n == 1:`-ийг `if n <= 1:` болго.

</details>

<Callout type="warning">
**⚠️ Анхаарах зүйлс**

- **Суурь тохиолдолд зөвшөөрөгдсөн бүх оролт хүрэх ёстой.** `n == 1` суурь тохиолдолтой `factorial(0)` суурь тохиолдолд хэзээ ч хүрэхгүй — Python-д `RecursionError`.
- **Ерөнхий тохиолдол суурь тохиолдол руу ойртох ёстой.** `factorial(n)` дотроос `factorial(n)`-ийг дахин дуудвал оролт жижгэрэхгүй.
- **«Рекурс хурдан» гэж бүү бич.** Ихэнхдээ давталтаас удаан, санах ой их зарцуулна; давуу тал нь ойлгомжтой, богино код.
- **Сурах бичгийн quicksort-ын Python кодонд алдаа бий** (374-р тал): `if start == finish` гэж зогсдог. Хэсэг хоосон болоход (`start > finish`) суурь тохиолдол ажиллахгүй, өөрийгөө ижил мужаар дахин дахин дуудна: дээрх кодын `>=`-ийг `==` болговол `[1, 2, 3, 4]` дээр `RecursionError` гарна. Java хувилбар шиг `start >= finish` гэж бич.

</Callout>

## B2.4.5 Рекурсив алгоритм зохиох ба мөшгих <HL />

> 🎯 **Зорилго:** **Construct** and **trace** recursive algorithms in a programming language — программчлалын хэлээр рекурсив алгоритм зохиож, мөшгих. Энэ хэсгийн төгсгөлд та:
>
> - Тодорхой суурь ба ерөнхий тохиолдолтой, салаалахгүй рекурсив функц бичнэ;
> - Рекурсив дуудлагыг параметр ба буцах утгатай хүснэгтээр мөшгинө;
> - Энгийн рекурсив функцийг давталттай хувилбартай харьцуулж, хөрвүүлнэ;
> - Рекурсив функц яагаад буруу ажиллаж байгааг олно.

### 🤔 Бодоод үзээрэй

Ангийн чатад «Маргааш биеийн тамир хэдэн цагт эхлэх вэ?» гэж асуулаа. Та мэдэхгүй тул Батаас, Бат мэдэхгүй тул Сараагаас асууна. Сараа хуваарь харж шууд хариулж, хариу Бат руу, тэндээс тан руу буцна — асуулт бүр ганц л хүн рүү явдаг нэг шулуун гинж. Хариулаарай:

```python
def sum_to(n):
    if n == 1:
        return 1
    return n + sum_to(n - 1)
```

1. Суурь тохиолдлыг нэрлэ. `sum_to(3)` юу буцаах вэ?
2. Рекурсив дуудлага бүр яагаад **жижиг** оролт авах ёстой вэ?
3. `sum_to(0)` дуудвал юу болох вэ?

<details>
<summary>Хариу</summary>

1. `n == 1` → 1. `sum_to(3)` = 3 + 2 + 1 = **6**.
2. Суурь тохиолдолд хүрэхийн тулд — Сараа шиг шууд хариулдаг хүнд хүрэх ёстой.
3. n нь 0, −1, −2… болж хэзээ ч 1 болохгүй → `RecursionError`. Суурь тохиолдлыг `n <= 1` болгож засна.

</details>

### 📖 Гол ойлголт

#### Рекурсив функц бичих 4 алхам

Энэ хичээлийн жор (сурах бичгийн factorial-ын тайлбараас):

1. Шууд хариулж чадах **хамгийн жижиг** тохиолдлыг ол — суурь тохиолдол (`n == 1`, хоосон мөр, `lower > upper`).
2. Том асуудлыг өөрийнх нь **жижиг** хувилбараар илэрхийл — ерөнхий тохиолдол (n! = n × (n − 1)!).
3. Дуудлага бүр суурь тохиолдол руу ойртож байгааг шалга.
4. Рекурсив дуудлагын үр дүнг **`return`**-ээр буцааж, нэгтгэ.

#### Мөшгих хүснэгт: `factorial(4)`

| Дуудлага | `n` | `n == 1`? | Буцах утга |
|---|---|---|---|
| `factorial(4)` | 4 | False | 4 × factorial(3) = **24** |
| `factorial(3)` | 3 | False | 3 × factorial(2) = 6 |
| `factorial(2)` | 2 | False | 2 × factorial(1) = 2 |
| `factorial(1)` | 1 | True | 1 |

Мөр бүр нэг дуудлага. Эхлээд дуудлагуудыг **доош** бөглө (ороох), дараа нь «Буцах утга» баганыг **доороос дээш** бөглө (тайлах). Эхний дуудлагын буцах утга бол хариу.

#### Салаалахгүй ба салаалах рекурс

- **Салаалахгүй рекурс (non-branching recursion):** түвшин бүрт **нэг л** рекурсив дуудлага ажиллана → дуудлагууд нэг гинж үүсгэнэ (factorial, `sum_to`). IB B2.4.5 зөвхөн ийм рекурсыг зохиохыг шаарддаг.
- **Салаалах рекурс (branching recursion):** нэг дуудлага өөрийгөө хоёр ба түүнээс олон удаа дуудна → мод хэлбэртэй, дуудлагын тоо хурдан өснө (Fibonacci, quicksort — B2.4.4).

#### Рекурс ба давталт

| | Рекурсив `sum_to(n)` | Давталттай `sum_to(n)` |
|---|---|---|
| Давтах арга | Өөрийгөө дуудна | `for i in range(1, n + 1)` давталт |
| Санах ой | Дуудлага бүрт нэг фрейм — O(n) | Хэдхэн хувьсагч — O(1) |
| Эрсдэл | Том n-д stack overflow (Python-д n ≈ 1000) | Нөхцөл буруу бол төгсгөлгүй давталт |
| Давуу тал | Богино, математик тодорхойлолттой яг адил | Ихэвчлэн хурдан, энгийн тоололтод аюулгүй |

#### Рекурсив код буруу ажиллах гурван шалтгаан

| Алдаа | Жишээ | Үр дүн |
|---|---|---|
| Суурь тохиолдолд хүрэхгүй | `n == 1` суурь тохиолдолтой `sum_to(0)` | `RecursionError` |
| Оролт жижгэрэхгүй | `return n + sum_to(n)` | `RecursionError` |
| `return` дутуу | `return n + sum_to(n - 1)`-ийн оронд `sum_to(n - 1)` | Функц `None` буцаана |

### 💻 Туршиж үзээрэй

Дөрвөн салаалахгүй рекурсив функц. Ажиллуулахаасаа өмнө мөр бүрийг таамагла:

```python
def power(base, exp):
    if exp == 0:                          # base case
        return 1
    return base * power(base, exp - 1)    # general case

def reverse(text):
    if len(text) <= 1:
        return text
    return reverse(text[1:]) + text[0]

def digit_sum(n):
    if n < 10:
        return n
    return n % 10 + digit_sum(n // 10)

def binary_search(numbers, key, lower, upper):
    if lower > upper:                     # base case 1: the range is empty
        return -1
    mid = (lower + upper) // 2
    if numbers[mid] == key:               # base case 2: found
        return mid
    if numbers[mid] < key:
        return binary_search(numbers, key, mid + 1, upper)
    return binary_search(numbers, key, lower, mid - 1)

print("power(2, 5) =", power(2, 5))
print("reverse('recursion') =", reverse("recursion"))
print("digit_sum(4721) =", digit_sum(4721))
data = [3, 4, 5, 7, 9, 11, 13]
print("search 11 ->", binary_search(data, 11, 0, len(data) - 1))
print("search 8  ->", binary_search(data, 8, 0, len(data) - 1))
```

```text
power(2, 5) = 32
reverse('recursion') = noisrucer
digit_sum(4721) = 14
search 11 -> 5
search 8  -> -1
```

- **Суурь тохиолдлууд:** `exp == 0`; 0 эсвэл 1 тэмдэгттэй мөр; нэг оронтой тоо; хоосон муж эсвэл олдсон.
- **Оролт жижгэрнэ:** `exp - 1`, `text[1:]` (зүсэлт, B2.1.2), `n // 10` (B2.1.1), муж хагаслана.
- **Буцахдаа нэгтгэнэ:** `*`, `+`, мөр залгах. Хоёртын хайлт хариугаа өөрчлөлгүй дамжуулна.
- `binary_search`-д хоёр рекурсив мөр байгаа ч дуудлага бүрт **нэг л** нь ажилладаг тул салаалахгүй; муж хагасалдаг тул O(log n) дуудлага.

1. `reverse("abc")`-ийг мөшги: дуудлага бүр ба буцах утга бүрийг бич.
2. `count_vowels(text)`-ийг рекурсаар бич: `"banana"` → 3. Зөвлөмж: `text[0]`-ийг шалгаад, `text[1:]` дээр рекурс хий.

<details>
<summary>Хариу</summary>

1. `reverse("abc")` → `reverse("bc") + "a"` → `reverse("c") + "b"` → `"c"` (суурь тохиолдол). Буцахдаа: `"c" + "b"` = `"cb"`, дараа нь `"cb" + "a"` = **`"cba"`**.
2. Нэг боломжит хариу:

```python
def count_vowels(text):
    if text == "":                       # base case: no letters left
        return 0
    if text[0] in "aeiou":
        return 1 + count_vowels(text[1:])
    return count_vowels(text[1:])
```

</details>

<Callout type="warning">
**⚠️ Анхаарах зүйлс**

- **`return`-ийг бүү март.** `return binary_search(...)`-ийн оронд зөвхөн `binary_search(...)` гэж бичвэл олсон хариу дуудсан газарт хүрэхгүй: хоёр мөрийн `return`-ийг хоёуланг нь орхивол функц `None` буцаана, нэгийг нь орхивол буруу хариу гарч болно.
- **Суурь тохиолдлыг ерөнхий тохиолдлоос өмнө шалга.** Эс бөгөөс функц зогсохоосоо өмнө дахин өөрийгөө дуудна.
- **Хамгийн жижиг оролтоор тест хий:** 0, 1, хоосон мөр `""`, ганц элементтэй жагсаалт.
- **Python-д гүн 1000 орчим.** `sum_to(5000)` → `RecursionError`, харин давталттай хувилбар асуудалгүй.
- **Fibonacci (сурах бичиг, 372-р тал) салаалах рекурс.** Сурах бичигт байгаа ч IB B2.4.5 зөвхөн салаалахгүй рекурсыг шаарддаг.

</Callout>

## Дүгнэлт

- **Big O:** n өсөхөд ажил хэрхэн өсөхийн дээд хязгаар (энэ модульд хамгийн муу тохиолдол). Давталт тоол: давхар давталт үржинэ, дараалсан нь нэмэгдэнэ; тогтмол үржвэр ба бага гишүүнийг хая. `O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)`.
- **Хайлт:** шугаман хайлт ямар ч дараалалд ажиллана, O(n). Хоёртын хайлт зөвхөн эрэмбэлэгдсэн өгөгдөлд, `lower`, `upper = len(numbers) - 1`, `mid = (lower + upper) // 2`, `while lower <= upper`, O(log n).
- **Эрэмбэлэлт:** хөөсөн — хөрш хосыг солино, `range(n - 1 - i)`, `swapped` тэмдгээр эрт зогсоно. Сонгон — `min_index`-ийг олж, дамжилтад нэг солилт. Хоёулаа O(n²) хугацаа, O(1) санах ой.
- **Рекурс (HL):** суурь тохиолдол зогсооно, ерөнхий тохиолдол суурь тохиолдол руу ойртоно; ороох үед фрейм push, тайлах үед pop. Quicksort: тулгуур элемент (pivot), хуваалт, хоёр хэсэгт рекурс, `start >= finish` суурь тохиолдол.
- **Рекурсив алгоритм (HL):** суурь тохиолдлыг эхэнд, рекурсив дуудлагын үр дүнг `return`-ээр буцаа. Мөшгихдөө дуудлагыг доош, буцах утгыг дээш бөглө.

| Алгоритм | Хугацаа (хамгийн муу тохиолдол) | Санах ой |
|---|---|---|
| Шугаман хайлт | O(n) | O(1) |
| Хоёртын хайлт | O(log n) | O(1) |
| Хөөсөн эрэмбэлэлт | O(n²) (эрт зогсох тэмдэгтэй бол хамгийн сайн тохиолдол O(n)) | O(1) |
| Сонгон эрэмбэлэлт | O(n²) | O(1) |

**Шалгалтад анхаар:**

- **Describe** (B2.4.1): Big O-г бичээд зогсохгүй, хаанаас гарсныг бич — «two nested loops over n → n × n → O(n²)».
- **Construct** (B2.4.2): `upper = len(numbers) - 1`, `lower <= upper`, `//`. Олдохгүй, эхний ба сүүлийн утгаар мөшгиж шалга.
- **Trace** (B2.4.3): дамжилт бүрийн дараах жагсаалтыг бич; асуулт ямар алгоритм, ямар эрэмбэ (өсөх/буурах) шаардаж байгааг давхар уншиж шалга.
- **Evaluate** (B2.4.3): харьцуулалт, солилт, эрт зогсолт, өгөгдлийн төрлөөр (бараг эрэмбэлэгдсэн, жижиг) жинлэ.
- **Explain / Construct** (HL): суурь тохиолдол, ерөнхий тохиолдол, ороох, тайлах, дуудлагын стек гэсэн нэр томьёог хэрэглэ; `return`-ийг бүү март.
- Байнга гардаг сэдвүүд: хоёртын хайлтад эрэмбэлэгдсэн өгөгдөл хэрэгтэй, O(n) ба O(log n)-ийг тоогоор жишээлэх (1 000 000 → 20), хөөсөн ба сонгон эрэмбэлэлтийн ялгаа, суурь тохиолдолгүй рекурс.
