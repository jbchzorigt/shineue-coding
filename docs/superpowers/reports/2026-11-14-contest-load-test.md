## Нэвтрэлтийн оргил: санах ой ба хугацаа (150 сурагч, хэмжсэн)

| Үзүүлэлт | Утга |
|---|---|
| Серверийн санах ой (private), тайван үед | 135 MiB |
| 150 зэрэг нэвтрэлтийн оргил | 732 MiB (+~600 MiB), 20 с дотор 150 MiB руу буцсан |
| Нэвтрэлт дуусах хугацаа, min / p50 / max | 6.8 / 6.8 / 6.9 с |

- Node-ийн `scrypt` libuv-ийн 4 урсгалтай thread pool дээр ажилладаг тул нэг процесс дээр зэрэг ажиллах хэшлэлт 4-өөс хэтрэхгүй: 4 × 128 MiB ≈ 512 MiB. Хэмжилт үүнтэй таарч байна, тиймээс **санах ой дуусах эрсдэл бага** (Vercel-ийн instance 2 GB).
- Бүх нэвтрэлт **нэг зэрэг** дууссан (min ≈ max). Хэшлэлт 4-өөр дараалсан бол 0.2 с-ээс 6.8 с хүртэл тархах ёстой. Магадгүй шалтгаан: нэвтрэлтийн сүүлийн алхам (session cookie-г шифрлэх WebCrypto) мөн thread pool-ийн дараалалд, бүх scrypt-ийн ард орж хүлээдэг. Шалтгааныг тусад нь баталгаажуулаагүй.
- Үүнээс гарах **жинхэнэ эрсдэл бол удаашрал:** нэвтрэлтийн оргил үед тэр instance дээрх thread pool ашигладаг бусад хүсэлт (session шалгах, файл унших) мөн хүлээнэ. Vercel-ийн 1 vCPU дээр хэшлэлт бүр local-аас удаан тул хүлээлт урт болно.

## Дүгнэлт

- **Сервер аль ч түвшинд унаагүй.** HTTP алдаа 0, буруу хариу 0, гэнэтийн timeout 0, санд бичигдсэн оноо 0 зөрүүтэй.
- **Tunnel бараг саатал нэмэхгүй:** p95 нь 4.2 → 4.4 с (10), 6.7 → 7.0 с (60). Гол хугацаа Piston дотор (тест бүрийг дараалан, 300 мс зайтай ажиллуулдаг) зарцуулагдана.
- Хариу хугацаа зэрэг илгээлтийн тоотой бараг шугаман өснө: 150 зэрэг илгээлтэд p95 12.6 с. Бодит тэмцээнд илгээлт минутад тархдаг тул энэ нь хангалттай нөөц.
- Сайтын урсгалд илгээлтийн p95 17–20 с гарсан нь төгсгөлгүй давталттай 10%-аас (5 тест × 3 с) болсон; ердийн илгээлтийн p50 3–9.5 с.

## Эрсдэл ба зөвлөмж

1. **Нэвтрэлтийн оргил → удаашрал.** Сурагчдыг тэмцээн эхлэхээс 5–10 минутын өмнө нэвтрүүлэх. Нэвтэрсэн сурагч дахин хэшлэлт хийлгэдэггүй тул эхлэх мөчид ачаалал үүсэхгүй.
2. **Quick tunnel тогтворгүй.** Тест хийх үед (2026-11-16) production-ий Piston tunnel унтарсан байсан. Тэмцээний өмнө `piston-tunnel.ts`-ээр сэргээж, сайтаас нэг бодлого илгээж шалгах; урт хугацаанд нэртэй (named) Cloudflare tunnel руу шилжих.
3. **`piston-tunnel.ts` засагдсан:** (а) зөвхөн `--url http://localhost:2000` tunnel-ийг зогсооно (өмнө нь бусад төслийн tunnel-ийг унтраадаг байсан); (б) хавтсыг deploy хийхийн оронд одоогийн production build-ийг шинэ хаягаар дахин build хийнэ (өмнө нь commit хийгээгүй кодыг migration-гүйгээр production руу илгээж байсан).
4. Piston-ий гаралт 1024 тэмдэгтээс хэтэрвэл сурагчид "хугацаа хэтэрсэн" гэж буруу мессеж харагддаг (тусад нь засах).
