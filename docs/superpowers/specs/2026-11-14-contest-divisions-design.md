# Тэмцээний ангилал (division) ба ачааллын тест

Огноо: 2026-11-14
Төлөв: Дизайн батлагдсан, spec хянагдаж байна
Өмнөх ажил: `2026-10-19-contest-approval-design.md` (дууссан, production-д гарсан)

## Зорилго

Удахгүй болох программчлалын тэмцээн дөрвөн ангилалтай: **6–7 анги**, **8–10 анги**, **11–12 анги**, **сонирхогчид**
(анги харгалзахгүй). Ангилал бүр өөрийн бодлоготой, өөрийн leaderboard-той. Мөн тэмцээний үеийн зэрэг хандалтад сервер
(ялангуяа код шалгагч Piston) тэсэх эсэхийг хэмжинэ.

### Хэрэглэгчийн шийдвэрүүд

- Ангилал бүр **өөр бодлоготой**; зарим бодлогыг хэд хэдэн ангилалд хуулж болно.
- Ангилал нь **ангиас автоматаар**; сонирхогчдын ангилалд ямар ч ангийн сурагч орно.
- Нэг сурагч өөрийн ангийн ангилал **ба** сонирхогчдын ангилалд зэрэг оролцож болно.
- Оролцогчид зөвхөн сургуулийн (`@shineue.edu.mn`) сурагчид.
- Арга **A**: ангилал бүр нь одоо байгаа тэмцээн; тэдгээрийг «цуврал»-аар бүлэглэнэ.
- Нэмэлтээр: зэрэг хандалтаар сервер унах эсэхийг тестлэнэ.

### Хүрээнээс гадуур

- Нэг бодлогыг хэд хэдэн тэмцээнд холбоос байдлаар хуваалцах (хуулбар л байна).
- Гадны (сургуулийн бус) оролцогчийн аккаунт.
- Цувралын нийлбэр leaderboard, ангилал хоорондын харьцуулалт.
- Production-ийн Vercel/Neon-ийг ачааллаар цохих (жинхэнэ өгөгдөлд илгээлт бичигдэнэ). Vercel функц өөрөө масштабладаг;
  гол эрсдэл нь Piston ба tunnel.

### Амжилтын шалгуур

1. Багш тэмцээний тохиргоонд «Цуврал» ба «Ангилал» (Бүх анги / Ангиас–хүртэл) оруулна; хадгалаад буцааж нээхэд хэвээр.
2. `/contests` дээр ижил цувралын тэмцээнүүд нэг картад, ангиллын дарааллаар (сонирхогчид сүүлд) харагдана.
3. «7A» ангийн сурагч 6–7 ба сонирхогчдын ангилалд бүртгүүлж чадна; 11–12-т сервер татгалзаж, «Таны анги (7) энэ ангилалд
   хамаарахгүй» гэж харагдана; хуудсанд «Оролцох»-ын оронд «Таны ангид хамаарахгүй».
4. Анги тодорхойгүй сурагч ангийн хязгаартай тэмцээнд бүртгүүлэхэд тэмцээний тохиргооноос үл хамааран **хүлээгдэж буй**
   болж, багш шийднэ.
5. Багш бодлогыг өөр тэмцээн рүү нууц тест, хариу хүснэгттэй нь хамт хуулна; ID давхцвал татгалзана.
6. Хуучин тэмцээнүүд (цувралгүй, хязгааргүй) өмнөх шигээ ажиллана.
7. Ачааллын тестийн тайлан: Piston (шууд ба tunnel-ээр) болон бүтэн submit урсгал (local) зэрэг 10/30/60/100/150 илгээлтэд
   алдаа, хугацаа (p50/p95/max), гацалт; хаана эвдэрч эхэлдэг; зөвлөмж.

## Өгөгдөл

`contests`:

| Багана | Төрөл | Тайлбар |
|---|---|---|
| `series` | `text` null | Цувралын нэр («Намрын тэмцээн 2026»); хоосон = энгийн тэмцээн |
| `grade_min` | `integer` null | Доод анги |
| `grade_max` | `integer` null | Дээд анги |

Check `contests_grade_range_check`: `(grade_min is null and grade_max is null) or (grade_min between 1 and 12 and
grade_max between grade_min and 12)`. Хоёулаа null = сонирхогчид (бүх анги). Хуучин мөрүүд null хэвээр.

Ангиллын нэрийг хадгалахгүй: `divisionLabel(contest)` → «6–7 анги» (`grade_min == grade_max` бол «9-р анги»), null бол
«Сонирхогчид».

## Дүрэм (цэвэр функцүүд, `src/lib/contest-division.ts`)

- `gradeOf(className: string | null): number | null` — ангийн нэрний эхний тоо, 1–12 бол тэр, үгүй бол null
  («7A»→7, «11B»→11, «A7»→null, «13A»→null, null→null).
- `divisionEligibility(contest, className)` → `{ kind: "open" } | { kind: "eligible" } | { kind: "unknown" } |
  { kind: "ineligible"; grade: number }`:
  - хязгааргүй → `open`; анги тодорхойгүй → `unknown`; хязгаарт багтвал `eligible`; эс бөгөөс `ineligible`.
- `groupContests(contests)` → цувралтай тэмцээнүүдийг цувралаар бүлэглэж, бүлэг дотор `grade_min` өсөхөөр (null хамгийн
  сүүлд), бүлгүүд болон цувралгүй тэмцээнүүдийг одоогийн дарааллаар (эхлэх цаг буурахаар; бүлгийнх нь хамгийн сүүлийн
  эхлэх цаг) буцаана.

## Бүртгэл (`registerParticipant`)

Транзакц дотор тэмцээн ба хэрэглэгчийн `class_name`-ийг уншиж:

- `ineligible` → `UserError("Таны анги (N) энэ ангилалд хамаарахгүй.")`, мөр үүсэхгүй;
- `unknown` → `pending` (тэмцээний `requires_approval`-аас үл хамааран);
- `open` / `eligible` → одоогийнх шиг (`requires_approval` бол `pending`, үгүй бол `approved`);
- мөр аль хэдийн байвал өөрчлөхгүй (одоогийнх шиг).

`registerForContest` action `UserError`-ийг барьж, тэмцээний хуудас руу redirect хийнэ (алдааны хуудас гарахгүй). Хуудас
шалтгааныг `divisionEligibility`-ээр өөрөө тооцож харуулдаг тул URL-аар мессеж дамжуулахгүй. Хуурамч POST ирсэн ч мөр
үүсэхгүй нь гол хамгаалалт.

## Хуудсууд

- `/contests`: `groupContests`-ээр карт; цувралын картад мөр бүр ангиллын нэр, хугацаа, төлөв, оролцогчийн тоо,
  «Оролцох»/төлөв; `ineligible` бол «Таны ангид хамаарахгүй» (бүдэг, товчгүй).
- `/contests/[id]`: гарчгийн доор «<цуврал> · <ангилал>»; бүртгэлгүй сурагчид `ineligible` → шалтгаан; `unknown` →
  «Багш таны ангийг шалгаж зөвшөөрнө» тайлбар «Оролцох» доор.
- Leaderboard: гарчигт ангиллын нэр.
- Багш: `ContestForm`-д «Цуврал» (`<datalist>`-аар одоо байгаа цувралууд) ба «Ангилал»: `Бүх анги (сонирхогчид)` /
  `Ангиас [n] хүртэл [m]`; `saveContest` баталгаажуулна («Ангийн хязгаар 1–12, доод нь дээдээсээ их биш»).
  `/teacher/contests` цувралаар бүлэглэнэ.
- Бодлого засах хуудас: «Өөр тэмцээн рүү хуулах» — зорих тэмцээний `<select>` (ижил цувралынх эхэнд), «Хуулах»;
  `copyProblem(fromContest, problemId, toContest)` нийтийн ба нууц хэсгийг хамт хуулна; зорихд ижил ID байвал
  `UserError("Тэр тэмцээнд «<id>» ID-тэй бодлого аль хэдийн байна.")`. Товчны дэргэд «Хуулбар бие даасан — нэгийг засахад
  нөгөө өөрчлөгдөхгүй».

## Ачааллын тест

`scripts/load-test.ts` (хөгжүүлэлтийн хэрэгсэл, commit-лэнэ), гурван горим:

1. **`piston <url>`** — N зэрэг «илгээлт»; илгээлт бүр `gradePython`-тэй адил T тестийг дараалан 300 мс зайтай
   ажиллуулна. Кодын холимог: 70% энгийн зөв бодолт, 20% ~1 с тооцоолол, 10% төгсгөлгүй давталт (3 с timeout).
   Түвшин: 10, 30, 60, 100, 150. Хэмжих: илгээлтийн нийт хугацаа p50/p95/max, сүлжээ/HTTP алдаа, буруу гаралт, timeout-ын
   тоо. `http://localhost:2000/api/v2` (шууд) ба tunnel URL дээр.
2. **`app <baseUrl>`** — бүтэн урсгал **зөвхөн local**: `next build && next start`, local DB, local Piston. Скрипт
   туршилтын тэмцээн ба K туршилтын сурагч (санамсаргүй нууц үгтэй, local DB-д) үүсгэж, NextAuth credentials-аар нэвтэрч,
   бүгд зэрэг `POST /api/contests/<id>/problems/<pid>/submit` илгээнэ. Хэмжих: HTTP статус (200/429/5xx), хугацаа,
   оноо зөв бичигдсэн эсэх (оролцогчийн нийт оноо = хамгийн сайн оноо), DB алдаа, процесс унасан эсэх. Дуусахад
   туршилтын өгөгдлийг устгана.
3. **`report`** — үр дүнг `docs/superpowers/reports/2026-11-14-contest-load-test.md` руу хүснэгтээр бичнэ.

Tunnel-ийн туршилт production-ий код шалгагчтай ижил Piston-ийг хэрэглэдэг тул **хэрэглэгч зөвшөөрсний дараа**, тэмцээн
явагдаагүй үед ажиллуулна. Production Vercel/Neon руу ачаалал явуулахгүй.

Шалгуур: алдаа 0, timeout зөвхөн төгсгөлгүй давталтынх, p95 < 20 с, max < 50 с (Vercel `maxDuration` 60 с). Аль түвшинд
эвдэрч эхэлснийг тайланд бичиж, засварын санал (Piston тохиргоо, тестийг зэрэг ажиллуулах, дараалал, 429 мессеж г.м.)
гаргана; засвар хийх эсэхийг хэрэглэгч шийднэ.

## Алдаа ба захын тохиолдол

- Багш ангиллын хязгаарыг бүртгэлийн дараа өөрчилбөл бүртгэлүүд хэвээр (шалгалт зөвхөн «Оролцох» үед).
- Ангийн хязгаарууд давхцаж тохируулагдвал систем хориглохгүй (багшийн хариуцлага); анги тодорхой сурагч хоёуланд нь
  орж чадна.
- Staff (багш, админ) бүртгэлгүйгээр бүх тэмцээнийг үзнэ (одоогийнх шиг); ангиллын шалгалт тэдэнд хамаарахгүй.
- Цувралын нэрийг зайгаар тайрч хадгална; хоосон бол null.

## Тест

- `gradeOf`, `divisionEligibility`, `divisionLabel`, `groupContests` — цэвэр unit тест.
- DB: шинэ талбаруудын round-trip; check constraint буруу хязгаарыг (8–6, 0, 13, нэг нь null) татгалзана;
  `registerParticipant` ineligible (мөргүй, `UserError`), unknown (pending, `requires_approval=false` үед ч), eligible,
  open; `copyProblem` нууц хэсэгтэй, ID давхцвал татгалзах, эх бодлого өөрчлөгдөхгүй.
- Хөтөч: цувралын карт, ineligible мөр, тохиргооны талбарууд, бодлого хуулах.
- Ачааллын тест: дээрх тайлан.
