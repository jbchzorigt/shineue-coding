# Логик хаалганы (Gate) бодлого

Огноо: 2026-09-29
Төлөв: Дизайн батлагдсан, spec хянагдаж байна
Өмнөх ажил: `2026-09-29-password-login-design.md` (дууссан)

## Зорилго

Python-ы кодын бодлоготой адил, логик хаалгаар хэлхээ зурж бодох шинэ төрлийн бодлого нэмэх. Сурагч
хаалгыг чирж тавиад утсаар холбоно. "Ажиллуулах" дарахад хэлхээний үнэний хүснэгт гарна.
"Илгээх" дарахад сервер шалгаж XP өгнө. IB-ийн "construct a logic diagram" даалгавартай яг таарна.

### Хэрэглэгчийн шийдвэрүүд

- Сурагч **хэлхээ зурж** хариулна (илэрхийлэл бичих, хүснэгт бөглөх хэлбэр биш).
- Gate бодлого **модуль дотор** (шинэ төрөл, XP, модуль нээх) болон **тэмцээнд** байна.
- Багш бодлого бүрт **зөвшөөрөгдөх хаалгын төрөл** ба **хаалгын дээд тоо**-г тавьж болно.
- **6 жишээ бодлого** бүхий "Логик хаалга" модуль бэлдэнэ.
- Editor-ыг **React Flow (`@xyflow/react`)** дээр бүтээнэ (A хувилбар).

### Хүрээнээс гадуур

Дараах зүйлс энэ ажилд орохгүй:

- 3 ба түүнээс олон оролттой хаалга (бүх хаалга 2 оролттой, NOT нь 1);
- дараалсан хэлхээ (flip-flop, санах ой), Карногийн карт;
- сурагч илэрхийлэл бичих эсвэл хүснэгт бөглөх хэлбэрийн хариулт;
- багшийн бэлдсэн эхлэлийн хэлхээ (starter circuit);
- илгээхээс өмнөх ноорог хадгалалт (Python-ы editor-т ч байхгүй). Зөвхөн сүүлд илгээсэн хэлхээ сэргээгдэнэ;
- тэмцээнд сүүлд илгээсэн хэлхээг сэргээх (Python-ы тэмцээнд ч байхгүй).

### Амжилтын шалгуур

1. Сурагч модулийн Gate бодлого дээр хаалга нэмж, утсаар холбож, "Ажиллуулах" дарахад үнэний хүснэгт гарна.
2. Зөв хэлхээ илгээхэд бодлого биелэгдэж XP нэмэгдэнэ. Буруу хэлхээ "6/8 мөр зөв" гэх мэт үр дүн авна.
3. Зөвшөөрөгдөөгүй хаалга, хэт олон хаалга, гогцоо, холбогдоогүй оролт/гаралттай хэлхээ тодорхой монгол алдаа авна. Сервер ч мөн адил татгалзана.
4. Хүснэгт нуугдсан бодлогын хүлээгдэж буй хүснэгт хөтөч рүү хэзээ ч очихгүй.
5. Багш модулийн болон тэмцээний Gate бодлогыг илэрхийлэл бичих эсвэл нүд дарах аргаар үүсгэж, засаж чадна.
6. Тэмцээнд Gate бодлого `points × зөв мөр / нийт мөр` оноо өгч, leaderboard-д тусна.
7. `scripts/import-content.ts` "Логик хаалга" модулийг, дараа нь `npm run script -- scripts/seed-logic.ts` 6 бодлогыг оруулна (хоёулаа дахин ажиллуулж болно).
8. `npm test`, `tsc`, `lint` (алдаа 0), `next build` бүгд амжилттай. Хөтөч дээрх гар шалгалт (§8) давсан байна.

## 1. Нэр томьёо ба өгөгдлийн хэлбэр

`src/lib/logic/` доторх цэвэр TypeScript модуль (DB, React хамааралгүй). Хөтөч болон сервер хоёулаа ашиглана.

```ts
export const GATE_TYPES = ["AND", "OR", "NOT", "NAND", "NOR", "XOR", "XNOR"] as const;
export type GateType = (typeof GATE_TYPES)[number];

/** Сурагчид харагдах бодлогын тохиргоо. */
export interface LogicSpec {
  inputs: string[];          // 1–4 ширхэг, нэг том латин үсэг: "A", "B", "C"
  outputs: string[];         // 1–4 ширхэг, нэг том латин үсэг: "Q", "S"
  allowed_gates: GateType[]; // дор хаяж 1, давхардалгүй
  max_gates: number | null;  // 1–60, null = хязгааргүй
  table_visible: boolean;    // хүлээгдэж буй хүснэгтийг сурагчид харуулах эсэх
}

/** Хүлээгдэж буй (эсвэл тооцоолсон) үнэний хүснэгт. */
export type TruthTable = string[];
```

**Нэрсийн дүрэм:** Оролт, гаралтын нэр бүр `/^[A-Z]$/` байна. Бүгд хоорондоо давхцахгүй (оролт, гаралт нийлээд).

**Үнэний хүснэгтийн хэлбэр:**
- `TruthTable` нь `2ⁿ` мөртэй (n = оролтын тоо).
- `i`-р мөр нь оролтын утгууд `i`-г n битээр бичсэнтэй тэнцэнэ. `inputs[0]` хамгийн ахлах бит.
  Жишээ нь A, B → мөрүүд `00, 01, 10, 11`.
- Мөр бүр гаралтын тоотой тэнцүү урттай `"0"`/`"1"` тэмдэгт мөр. Тэмдэгтүүд `outputs`-ийн дарааллаар байна.
  Жишээ нь half adder (S, C): `["00", "10", "10", "01"]`.

**Хэлхээний JSON** (сурагчийн хариулт, `code_snapshot` болон `contest_submissions.code`-д хадгалагдана):

```ts
export interface Circuit {
  gates: { id: string; type: GateType; x: number; y: number }[];
  wires: { from: string; to: string; port: number }[];
}
```

- `from` нь хаалганы `id` эсвэл оролтын терминал `in:A`.
- `to` нь хаалганы `id` эсвэл гаралтын терминал `out:Q`.
- `port` нь хаалганы оролтын дугаар: NOT-д 0, бусдад 0 эсвэл 1. Гаралтын терминалд 0.
- Хаалганы `id`: `/^[a-z0-9_-]{1,24}$/`, давхцахгүй. `x`, `y`: `|v| ≤ 100000` бодит тоо.
- Терминалуудын байрлал хадгалагдахгүй. Editor тэдгээрийг spec-ээс тооцоолж зурна.

| Файл | Экспорт | Үүрэг |
|---|---|---|
| `gates.ts` | `GATE_TYPES`, `GateType`, `gateArity(t)`, `applyGate(t, a, b)` | 7 хаалганы утга |
| `spec.ts` | `LogicSpec`, `TruthTable`, `rowInputs(n, row)`, `parseLogicSpec(spec, table)` | Spec болон хүснэгтийн шалгалт |
| `circuit.ts` | `Circuit`, `parseCircuit(raw)` | Итгэлгүй өгөгдлийг Circuit болгох |
| `evaluate.ts` | `LogicError`, `validateCircuit(c, spec)`, `truthTable(c, spec)` | Бүтцийн шалгалт, хүснэгт тооцох |
| `expression.ts` | `parseExpression(src, inputs)`, `expressionTable(...)` | Багшийн формын илэрхийлэл |
| `grade.ts` | `gradeLogic(spec, expected, raw)` | Модуль болон тэмцээний дүн |

### 2.1 `parseCircuit(raw: unknown)`

`raw` нь JSON мөр эсвэл аль хэдийн задарсан объект байж болно. Буцаах утга:
`{ ok: true, circuit } | { ok: false, message: "Хэлхээ буруу форматтай байна." }`.

Дараах тохиолдолд татгалзана:
- JSON мөрийн урт 20000 тэмдэгтээс их;
- хэлбэр таарахгүй;
- үл мэдэгдэх хаалганы төрөл;
- хаалга 60-аас, утас 200-аас их;
- `id` давхардсан эсвэл дүрэм зөрчсөн;
- координат буруу.

Энд spec-ийг харгалзахгүй (терминалын нэрийг §2.2 шалгана).

### 2.2 `validateCircuit(circuit, spec): LogicError[]`

`LogicError = { message: string; gateIds?: string[] }`. Хоосон массив бол хэлхээ зөв. UI `gateIds`-д орсон хаалгуудыг улаанаар тодруулна.
Ижил мессежтэй алдаанууд нэг алдаа болж нэгдэн, `gateIds`-д бүх холбогдох хаалга орно.
Шалгалтын дараалал болон мессежүүд:

1. **Зөвшөөрөгдөөгүй хаалга** (хаалга бүрд): `"{T} хаалга энэ бодлогод зөвшөөрөгдөөгүй."`
2. **Хэт олон хаалга:** `"Хаалга хэт олон байна: {n} / {max}."`
3. **Утасны буруу төгсгөл:** Дараах тохиолдолд `"Хэлхээ буруу форматтай байна."` (UI ийм утас үүсгэдэггүй):
   - `from`/`to` нь байхгүй хаалга эсвэл spec-д байхгүй терминалыг заасан;
   - `from` нь `out:…`, эсвэл `to` нь `in:…`;
   - `port` нь хаалганы arity-аас хэтэрсэн (гаралтын терминалд 0-ээс өөр).
4. **Нэг оролтод хоёр утас** (хаалганы порт эсвэл гаралтын терминал): `"Нэг оролтод хоёр утас холбогдсон байна."` (`gateIds`-тай).
5. **Холбогдоогүй хаалганы оролт:** `"{T} хаалганы оролт холбогдоогүй байна."` (`gateIds`-тай).
6. **Холбогдоогүй гаралт:** `"{Q} гаралт холбогдоогүй байна."`
7. **Гогцоо** (Kahn-ий topological sort): `"Хэлхээнд гогцоо байна — хаалганы гаралт өөрийнхөө оролт руу буцаж орсон."`
   Гогцоонд орсон (эсвэл гогцооноос тэжээгддэг) хаалгууд `gateIds`-д орно.

Ямар ч гаралтад хүрдэггүй хаалга зөвшөөрөгдөнө. Гэхдээ хаалгын тоонд орж, оролтууд нь холбогдсон байх ёстой.

### 2.3 `truthTable(circuit, spec): TruthTable`

`validateCircuit` хоосон үед л дуудагдана. Topological дарааллаар `2ⁿ` мөр бүрийг тооцно (≤ 16 × 60 алхам).

Мөн editor-ын шууд симуляцид зориулж нэг мөрийн утгыг тооцох `evaluateRow(circuit, spec, inputBits)` экспортлоно.
Энэ функц хаалга, терминал бүрийн утгыг `Map<string, 0|1|null>` хэлбэрээр буцаана. Холбогдоогүй оролттой хаалганы утга `null` байна.

### 2.4 `gradeLogic(spec, expected, raw)`

```ts
type LogicGrade =
  | { status: "malformed"; message: string }                       // parseCircuit амжилтгүй → 400
  | { status: "invalid"; circuit: Circuit; errors: LogicError[] }   // бүтцийн алдаа → амжилтгүй оролдлого
  | { status: "graded"; circuit: Circuit; table: TruthTable; correctRows: number; totalRows: number };
```

`parseCircuit` → `validateCircuit` → `truthTable` → `expected`-тэй мөр мөрөөр нь харьцуулна.
Мөр бүрийн бүх гаралт таарвал тэр мөр зөв. `passed = status === "graded" && correctRows === totalRows`.

### 2.5 `expression.ts`

- Бичиглэл: хувьсагч (spec-ийн оролтууд), `AND OR NOT NAND NOR XOR XNOR`, хаалт `( )`. Том жижиг үсэг ялгахгүй.
- Эрэмбэ (өндрөөс нам): `NOT` > `AND`, `NAND` > `XOR`, `XNOR` > `OR`, `NOR`. Хоёр талт операторууд зүүнээс баруун тийш.
- `parseExpression` буцаах утга: `{ ok: true, ast } | { ok: false, message }`. Мессежид тэмдэгтийн байрлалыг заана.
  Жишээ: `"1-р тэмдэгтэд нээсэн хаалт хаагдаагүй байна."`, `"«D» гэсэн оролт алга."`
- `expressionTable(exprs: string[], spec)` нь гаралт бүрийн илэрхийллээс `TruthTable` гаргана.

### 2.6 `parseLogicSpec(spec, table)` / `parseLogicSpecJson(specJson, tableJson)`

Буцаах утга: `{ ok: true, spec, table } | { ok: false, errors: string[] }`. Амжилттай бол цэвэрлэсэн хуулбар
(илүүдэл түлхүүргүй, хаалгууд `GATE_TYPES`-ийн дарааллаар) буцаана. Багшийн action болон seed script ашиглана. Дараахыг шалгана:
- §1-ийн нэрсийн дүрэм;
- оролт 1–4, гаралт 1–4;
- `allowed_gates` хоосон биш, давхардалгүй, зөвхөн `GATE_TYPES`-ээс;
- `max_gates` нь null эсвэл 1–60 бүхэл тоо;
- хүснэгт `2ⁿ` мөртэй, мөр бүр гаралтын тоотой тэнцүү урттай `0/1` мөр.

## 4. Багшийн засварлагч

Шинэ client компонент `src/components/teacher/logic-spec-fields.tsx` бодлогын формд болон тэмцээний бодлогын формд хоёуланд нь ашиглагдана.

- **Оролтууд** (`A, B, C`) болон **Гаралтууд** (`Q`) текст талбар. Таслалаар тусгаарлана.
- **Зөвшөөрөгдөх хаалгууд:** 7 checkbox, IB дүрстэй. Анхдагчаар бүгд сонгогдсон.
- **Хаалгын дээд тоо:** тоо. Хоосон бол хязгааргүй.
- **"Үнэний хүснэгтийг сурагчид харуулах"** checkbox.
- **Хүлээгдэж буй хүснэгт:**
  - Гаралт бүрт илэрхийллийн талбар байна. "Хүснэгт бөглөх" товч дарахад `expressionTable`-ээр хүснэгт бөглөгдөнө. Алдаа гарвал талбарын доор харагдана.
  - Хүснэгтийн гаралтын нүд бүр дээр дарахад 0↔1 солигдоно.
  - Оролт, гаралтын тоо өөрчлөгдөхөд хүснэгт шинэ хэмжээнд бүгд 0-ээр дахин үүснэ.
- Бүх утга нуугдмал `logic_spec` болон `expected_table` JSON талбараар илгээгдэнэ.
  Server action (`saveChallenge`, `saveContestProblem`) эдгээрийг `parseLogicSpecJson`-оор шалгаж, алдааг формд буцаана.
- Бодлогын формд төрлийн жагсаалтад "Логик хэлхээ (Gate)" нэмэгдэнэ.
  Тэмцээний бодлогын формд "Төрөл: Python / Логик хэлхээ" сонголт нэмэгдэнэ. Logic үед starter code болон тестийн талбарууд нуугдана.
- Модулийн болон багшийн content хуудсан дахь төрлийн шошгонд `logic: "Логик хэлхээ"` нэмэгдэнэ.

### 5.2 Canvas-ын дүрэм

- **Терминалууд:**
  - Оролтын терминалууд (A, B, …) зүүн талд босоо байрлана. Тус бүр 0/1 унтраалгатай.
  - Гаралтын терминалууд (Q, …) баруун талд гэрэл хэлбэрээр байрлана.
  - Терминалуудыг устгах, чирэх боломжгүй.
- **Palette:** Зөвхөн `allowed_gates` харагдана. Дарахад canvas-ын харагдаж буй төвд хаалга нэмэгдэнэ.
  `max_gates`-д хүрсэн бол товчнууд идэвхгүй болж, "Хаалга: 5/5" гэж харагдана.
- **Утас:**
  - Хаалга эсвэл оролтын терминалын гаралтын цэгээс хаалганы оролт эсвэл гаралтын терминал руу чирж холбоно.
  - Эзэлсэн оролт руу холбовол хуучин утас солигдоно. Гогцоо үүсгэх холболтыг editor шууд хүлээж авахгүй.
  - Гаралтаас хэд ч утас салаалж болно.
- **Устгах:** Сонгоод Delete/Backspace эсвэл 🗑 товч. ↺ товч бүх хаалга, утсыг цэвэрлэнэ (confirm асууна).
- **Шууд симуляци:** Унтраалгын утгаар `evaluateRow` тооцоологдоно. 1 утгатай утас ногоон, 0 утгатай нь саарал,
  тодорхойгүй нь тасархай шугамаар харагдана. Гаралтын гэрэл 1 үед асна.

### 5.3 Товчнууд ба үр дүн

- **Ажиллуулах** (сервергүй):
  - `validateCircuit` алдаатай бол жагсаалтаар харуулж, холбогдох хаалгуудыг улаанаар тодруулна.
  - Алдаагүй бол бүрэн үнэний хүснэгт гарна: оролтын баганууд болон "Таны {Q}" баганууд.
  - `table_visible` үед "Хүлээгдэж буй {Q}" баганууд болон мөр бүрт ✓/✗ нэмэгдэнэ.
- **Илгээх:** `POST /api/challenges/{id}/submit` руу `{ circuit, mode: "submit" }` илгээнэ.
  - Хариу нь "8/8 мөр зөв — бодлого биелэгдлээ!" эсвэл "6/8 мөр зөв".
  - Нууц хүснэгттэй бодлогод аль мөр буруу болохыг харуулахгүй.
  - XP болон модуль нээгдэх мессеж Python-ынхтой адил.
- **Hint:** Одоогийн hint API болон 30%-ийн хасалт хэвээр.
- **Эхлэл:** `code_snapshot`-ийг `parseCircuit`-ээр сэргээнэ. Амжилтгүй эсвэл хоосон бол зөвхөн терминалтай хоосон canvas.
  Snapshot-д байгаа ч одоо зөвшөөрөгдөөгүй хаалгууд хэвээр харагдаж, "Ажиллуулах" дарахад алдаа өгнө.

### 5.4 Хуудсууд

- `src/app/challenges/[challengeId]/page.tsx`: `type === "logic"` үед `LogicWorkspace`-ийг харуулна.
  - `table_visible` үед л `getChallengePrivate`-аас `expected_table`-г авч дамжуулна.
  - `logic_spec` байхгүй (гэмтсэн) бол "Бодлогын тохиргоо дутуу байна." гэж харуулна.
- `src/app/contests/[contestId]/problems/[problemId]/page.tsx`: `kind === "logic"` үед `LogicWorkspace` нь тэмцээний горимд ажиллана.
  Энэ горимд hint байхгүй, илгээх URL нь тэмцээний route, үр дүнд оноо харагдана.

## 6. Сервер

### 6.1 Модулийн submit (`src/app/api/challenges/[challengeId]/submit/route.ts`)

- `case "logic"`: `body.circuit`-ийг `gradeLogic(challenge.logic_spec, private.expected_table, body.circuit)`-д өгнө.
  - `logic_spec` эсвэл `expected_table` байхгүй бол 500 биш, "Бодлогын тохиргоо дутуу байна. Багшдаа хэлнэ үү." (409) буцаана.
  - `parseCircuit` амжилтгүй бол (UI ийм юм илгээдэггүй) оролдлого бүртгэхгүйгээр 400
    "Хэлхээ буруу форматтай байна." буцаана. Хоосон кодыг Python-д 400-аар татгалздагтай адил.
  - `validateCircuit` алдаатай бол амжилтгүй оролдлого гэж бүртгэнэ (Python-ы алдаатай кодтой адил). Хариунд `errors` орно.
  - Алдаагүй бол `passed = correctRows === totalRows`. Хариунд `{ correctRows, totalRows }` орно.
  - Бүртгэгдсэн оролдлого бүрийн snapshot нь `JSON.stringify(circuit)` (задалсан, цэвэрлэсэн хэлбэр).
    Ингэснээр дуусаагүй хэлхээ ч дараагийн удаа сэргээгдэнэ.
- Хариуны хэлбэр одоогийн `passed`, XP, модуль нээх талбаруудыг хэвээр хадгалж, шинэ `logic?: { correctRows, totalRows, errors? }` блок нэмнэ.
- Одоогийн 3 секундын cooldown, эрх шалгалт, `recordSubmission` хэвээр.
- Сервер хөтчийн тооцсон хүснэгтэд хэзээ ч итгэхгүй.

### 6.2 Тэмцээний submit (`.../contests/[contestId]/problems/[problemId]/submit/route.ts`)

- `problem.kind === "logic"` үед body `{ circuit }`, `gradeLogic` ашиглана.
- Буруу формат бол 400, оролдлого бүртгэхгүй (§6.1-тэй адил).
- `score = ok ? round(points × correctRows / totalRows) : 0`, `passed_tests = correctRows`, `total_tests = totalRows`
  (бүтцийн алдаатай үед `0 / 2ⁿ`).
- `contest_submissions.code`-д хэлхээний JSON хадгалагдана. Одоогийн цаг, бүртгэл, оноо хадгалах логик хэвээр.
- Хариунд оноо, `maxPoints`, `logic` блок орно.

## 8. Тест

**Unit (`node:test`, `src/lib/logic/*.test.ts`):**
- `gates`: 7 хаалганы бүх оролтын хослол.
- `circuit`: зөв JSON; мөр/объект оролт; хэмжээ, тоо, id, координатын хязгаар; үл мэдэгдэх төрөл.
- `evaluate`: зөвшөөрөгдөөгүй хаалга; хэт олон хаалга; буруу терминал; давхар утас; холбогдоогүй оролт/гаралт;
  гогцоо (`gateId`-тай); ашиглагдаагүй хаалга зөвшөөрөгдөх; half adder хүснэгт; `evaluateRow`-ийн `null`.
- `expression`: эрэмбэ (`A OR B AND C`, `NOT A AND B`, `A XOR B OR C`); хаалт; том жижиг үсэг; алдааны мессеж ба байрлал; үл мэдэгдэх хувьсагч.
- `spec`: нэрсийн дүрэм, давхардал, хүснэгтийн хэмжээ.
- `grade`: зөв, хагас зөв, алдаатай, буруу формат.

**DB (`src/lib/db/*.test.ts`):**
- logic бодлого хадгалах/унших, `getChallenge`-д `expected_table` ороогүй байх;
- `kind = 'logic'` тэмцээний бодлого хадгалах/унших, `getProblem`-д `expected_table` ороогүй байх;
- `type = 'logic'` check constraint-ийг давах.

**Хөтөч дээрх гар шалгалт:**
1. Сурагчаар 1-р бодлогыг нээж, AND нэмэн холбоод унтраалга, гэрэл, утасны өнгийг шалгах.
2. "Ажиллуулах" дарж хүснэгт ба ✓/✗ гарахыг шалгах.
3. Буруу хэлхээ илгээхэд "x/4 мөр зөв", зөв хэлхээ илгээхэд XP нэмэгдэхийг шалгах.
4. Гогцоо, холбогдоогүй оролт, NAND-only бодлогод AND нэмэх боломжгүй, хаалгын тооны хязгаар зэрэгт алдаа гарахыг шалгах.
5. Хуудсыг дахин ачаалахад сүүлд илгээсэн хэлхээ сэргэх.
6. 2-р бодлогын HTML/RSC payload-д хүлээгдэж буй хүснэгт байхгүйг шалгах.
7. Багшаар илэрхийллээр бодлого үүсгэх, нүд дарж засах, буруу илэрхийлэлд алдаа гарах.
8. Тэмцээнд logic бодлого нэмж, сурагчаар илгээн оноо болон leaderboard-ийг шалгах.
9. Утасны өргөн (375px) болон хуруугаар чирэх (эмуляц).
