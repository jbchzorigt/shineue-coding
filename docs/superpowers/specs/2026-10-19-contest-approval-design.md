# Тэмцээнд оролцох хүсэлт ба багшийн зөвшөөрөл

Огноо: 2026-10-19
Төлөв: Дизайн батлагдсан, spec хянагдаж байна
Өмнөх ажил: `2026-10-01-contest-submissions-design.md` (дууссан)

## Зорилго

Одоо сурагч «Оролцох» дармагц `contest_participants`-д бичигдэж, тэмцээн эхлэхэд бодлогуудыг шууд үзэж, илгээнэ.
Энэ ажлаар «Оролцох» нь **хүсэлт** болно: хүсэлт «хүлээгдэж буй» төлөвт орж, багш эсвэл админ зөвшөөрсний дараа л
сурагч оролцогч болно. Зөвшөөрөл шаардах эсэхийг тэмцээн бүрт багш сонгоно.

### Хэрэглэгчийн шийдвэрүүд

- Хамрах хүрээ: **тэмцээн бүрт тохиргоо** («Оролцоход багшийн зөвшөөрөл шаардах»).
- Татгалзвал: сурагч **«Таны хүсэлтийг татгалзсан»** гэж харна, дахин хүсэлт илгээж чадахгүй; багш дараа нь зөвшөөрч болно.
- Олноор: **«Бүгдийг зөвшөөрөх»** болон **ангиар** зөвшөөрөх товч.
- Одоо бүртгэлтэй оролцогчид: **зөвшөөрөгдсөн** гэж үзнэ.
- Шийдэх эрх: багш ба админ (`isStaff`).

### Хүрээнээс гадуур

- Зөвшөөрсөн оролцогчийг буцаах / хасах (илгээлтүүдтэй нь холбоотой тул дараа шаардлагатай бол).
- Сурагч хүсэлтээ өөрөө цуцлах.
- Имэйл / push мэдэгдэл. Сурагч төлөвөө тэмцээний хуудаснаас харна.
- Багш сурагчийг хүсэлтгүйгээр шууд нэмэх.

### Амжилтын шалгуур

1. Зөвшөөрөл шаарддаг тэмцээнд «Оролцох» дарсан сурагч «Хүсэлт илгээсэн — багш зөвшөөрөхийг хүлээж байна» гэж
   харна; бодлогын хуудас руу шилжихэд тэмцээний хуудас руу буцаана; илгээх API 403 буцаана.
2. Зөвшөөрөл шаарддаггүй тэмцээнд «Оролцох» нь өмнөх шигээ шууд оролцогч болгоно.
3. Багшийн тэмцээний хуудсанд «Хүсэлтүүд» хэсэг: хүлээгдэж буй хүсэлтүүд (нэр, анги, имэйл, цаг) мөр бүрт
   «Зөвшөөрөх» / «Татгалзах»; «Бүгдийг зөвшөөрөх»; анги сонгоод тэр ангийн хүлээгдэж буй хүсэлтүүдийг зөвшөөрөх;
   татгалзсан хүсэлтүүд «Зөвшөөрөх» товчтой.
4. Зөвшөөрсний дараа сурагч бодлогуудыг үзэж (тэмцээн эхэлсэн бол), илгээж чадна.
5. Татгалзсан сурагч «Таны хүсэлтийг татгалзсан» гэж харж, «Оролцох» товч гарахгүй.
6. Leaderboard, оролцогчийн тоо, «Дүн» CSV, илгээлтийн хуудасны сурагчийн шүүлтүүрт зөвхөн зөвшөөрөгдсөн оролцогч орно.
7. Багшийн тэмцээний жагсаалтад хүлээгдэж буй хүсэлтийн тоо харагдана.
8. Migration-ий дараа хуучин оролцогчид бүгд `approved`, хуучин тэмцээнүүд бүгд `requires_approval = true`;
   хуучин оролцогчдын оноо, илгээлт өөрчлөгдөхгүй.

## Өгөгдөл

`contests`:

| Багана | Төрөл | Тайлбар |
|---|---|---|
| `requires_approval` | `boolean not null default true` | Хуучин мөрүүд ч `true` болно |

`contest_participants`:

| Багана | Төрөл | Тайлбар |
|---|---|---|
| `status` | `text not null default 'approved'` + check `in ('pending','approved','rejected')` | Хуучин мөрүүд `approved`; шинэ хүсэлтийн утгыг код тавина |
| `decided_by` | `text` (users.uid, `on delete set null`) | Сүүлд шийдсэн багш/админ |
| `decided_at` | `timestamp with time zone` | Сүүлд шийдсэн цаг |

Индекс: `(contest_id, status)` — хүлээгдэж буй хүсэлтийн тоо, жагсаалтад.

`status`-ийн default нь `approved` — migration хуучин мөрүүдийг зөвшөөрөгдсөн болгоно. Шинэ бичлэгийн утгыг
`registerParticipant` тэмцээний `requires_approval`-аас хамаарч тавина (default-д найдахгүй).

## Сервер логик (`src/lib/db/contests.ts`)

- `Contest` төрөлд `requires_approval: boolean`; `upsertContest` хадгална.
- `ParticipantStatus = "pending" | "approved" | "rejected"`; `Participant`-д `status`, `registered_at`.
- `registerParticipant(contestId, user)` → `ParticipantStatus` буцаана:
  - тэмцээний `requires_approval` уншиж, `pending` эсвэл `approved`-аар оруулна;
  - мөр аль хэдийн байвал (давтан дарсан, татгалзсан ч) **өөрчлөхгүй** (`on conflict do nothing`), одоогийн төлөвийг буцаана.
- `getParticipant` — төлөвөөс үл хамааран мөрийг буцаана (дуудагч `status`-ийг шалгана).
- `listParticipants(contestId)` — **зөвхөн `approved`** (leaderboard, тоо, CSV, илгээлтийн шүүлтүүр өөрчлөлтгүй зөв болно).
- `listRequests(contestId)` — `pending` ба `rejected`, бүртгүүлсэн цагаар өсөхөөр, анги (`users.class_name`)-тай.
- `countPending(contestIds)` → `Map<contestId, number>` (багшийн жагсаалт).
- `decideRequests(contestId, uids, decision, staffUid)` → өөрчлөгдсөн мөрийн тоо:
  - `approved`: `pending` эсвэл `rejected` мөрүүдийг зөвшөөрнө;
  - `rejected`: зөвхөн `pending` мөрүүдийг татгалзана (зөвшөөрсөн оролцогчийг буцаахгүй);
  - `decided_by`, `decided_at = now()` тавина; нэг SQL update.
- `applySubmissionScore` — оролцогч `approved` биш бол `NotFoundError` (API-ийн шалгалтын давхар хамгаалалт).

## Серверийн үйлдлүүд (`src/lib/contest-actions.ts`)

- `registerForContest` — өөрчлөлтгүй урсгал; `registerParticipant`-ийн шинэ буцаах утгыг ашиглахгүй ч болно (хуудас төлөвийг уншина).
- `decideContestRequests(contestId, decision, form)` — `requireStaff`; form-оос нэг эсвэл олон `uid`, эсвэл
  `scope=all` / `scope=class:<анги>`:
  - `all` → `listRequests`-ийн бүх `pending` uid;
  - `class:<анги>` → тэр ангийн `pending` uid;
  - дараа нь `decideRequests`; `revalidatePath` (багшийн хуудас, тэмцээний хуудас, leaderboard, жагсаалт).
- `saveContest` — form-ын `requires_approval` checkbox-ыг уншина (байхгүй = `false`).

## Хуудсууд

- `/contests` (жагсаалт): оролцогчийн тоо = зөвшөөрөгдсөн; сурагчийн тэмдэг «Бүртгүүлсэн» / «Хүлээгдэж байна» /
  «Татгалзсан»; «Оролцох» зөвхөн мөргүй бол.
- `/contests/[id]`: `approved` → одоогийн харагдац; `pending` → цагтай карт «Хүсэлт илгээсэн — багш зөвшөөрөхийг
  хүлээж байна»; `rejected` → «Таны хүсэлтийг татгалзсан. Асуух зүйл байвал багштайгаа ярина уу.»; мөргүй →
  «Оролцох» (зөвшөөрөл шаарддаг бол доор нь «Багш зөвшөөрсний дараа оролцоно» гэсэн тайлбар).
- `/contests/[id]/problems/[pid]`: зөвхөн `approved` (эсвэл staff) үзнэ, бусдыг тэмцээний хуудас руу.
- `POST /api/contests/[id]/problems/[pid]/submit`: оролцогч `approved` биш бол 403
  «Багш таны хүсэлтийг зөвшөөрөөгүй байна.» (`pending`) / «Таны хүсэлтийг татгалзсан.» (`rejected`).
- Leaderboard: `listParticipants`-аар аль хэдийн зөвхөн зөвшөөрөгдсөн.
- `/teacher/contests`: тэмцээн бүрт «N хүсэлт хүлээгдэж байна» тэмдэг (N > 0 үед).
- `/teacher/contests/[id]`: `ContestForm`-д «Оролцоход багшийн зөвшөөрөл шаардах» checkbox (шинэ тэмцээнд
  анхдагчаар асаалттай, засахад одоогийн утга); бодлогуудын картын дээр «Хүсэлтүүд» карт:
  - хүлээгдэж буй: мөр бүрт нэр, анги, имэйл, огноо, «Зөвшөөрөх», «Татгалзах»;
  - дээр нь «Бүгдийг зөвшөөрөх (N)» ба анги бүрийн «10А (k) зөвшөөрөх» товчнууд (хүлээгдэж буй хүсэлттэй ангиуд);
  - «Татгалзсан» дэд жагсаалт, мөр бүрт «Зөвшөөрөх»;
  - хүсэлт байхгүй бол «Хүлээгдэж буй хүсэлт алга.»; тэмцээн зөвшөөрөл шаарддаггүй бол тайлбар мөр.

## Алдаа ба захын тохиолдол

- Хоёр багш нэг хүсэлтийг зэрэг шийдвэл сүүлийнх нь хүчинтэй; `rejected` нь зөвхөн `pending`-ийг өөрчилдөг тул
  аль хэдийн зөвшөөрсөн мөрийг нөгөө багшийн «Татгалзах» буцаахгүй.
- Тэмцээн дууссаны дараа ч багш шийдэж болно (оноо, илгээлт өөрчлөгдөхгүй; зөвхөн leaderboard-д харагдах эсэх).
- Тэмцээний тохиргоог `true` → `false` болговол хүлээгдэж буй хүсэлтүүд автоматаар зөвшөөрөгдөхгүй; багш «Бүгдийг
  зөвшөөрөх» дарна (хуудсан дээр санамж).
- Хэрэглэгч устгагдвал мөр cascade-аар устна (одоогийнх шиг); шийдсэн багш устгагдвал `decided_by` null.
- Staff өөрөө «Оролцох»-гүй — бүх бодлогыг үргэлж үзнэ (одоогийнх шиг).

## Тест

`node:test` + local Postgres (`--test-concurrency=1`), одоогийн `contests.test.ts` хэв маяг:

- `requires_approval` тэмцээнд бүртгэл `pending`, шаарддаггүйд `approved`; давтан бүртгэл төлөвийг өөрчлөхгүй
  (`rejected` хэвээр).
- `listParticipants` зөвхөн `approved`; `listRequests` `pending`+`rejected`, анги-тай.
- `decideRequests`: approve (pending→approved, rejected→approved), reject (pending→rejected, approved хэвээр),
  `decided_by`/`decided_at` тавигдана, буцаах тоо зөв.
- `countPending` олон тэмцээнд.
- `applySubmissionScore` `pending` оролцогчид `NotFoundError`, илгээлт бичигдэхгүй.
- Migration: одоогийн оролцогч `approved` (test helper-ийн migrate-аар шинэ схем үүсгэгдэх тул default-ийг шалгана).
- Хөтчөөр: сурагчийн хүсэлт → багш зөвшөөрөх → бодлого илгээх; ангиар зөвшөөрөх; татгалзах харагдац.
